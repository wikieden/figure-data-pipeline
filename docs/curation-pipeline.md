# 数据清洗·分割·处理·加工：详细方式与技术方向

> 2026-08-29。curation 层（M2）与数据处理的实施规范。各环节的开源算法/模型选型与传统 vs AI 论证见 [cleaning-algo-selection.md](cleaning-algo-selection.md)，承接 [architecture.md](architecture.md) §2 与 [index-replica-plan.md](index-replica-plan.md) §3–4。原则：清洗要狠、标注要浅而自动；清洗是标记不是删除（raw 永存，隐私脱敏除外）；每个处理步骤产出可追溯（lineage）。

## 0. 总览：episode 状态机

```
raw ──技术校验──► ingested ──质量门L1──► gated ──L2/L3──► scored
     └─(拒收:损坏/不完整)         └─(flag:reject_*)      │
                                                        ▼
training_ready ◄──打包── labeled ◄──标注/伪标签── segmented ◄──分割──
      │
      ├──► 训练分片（LeRobotDataset v3）
      └──► 演示库（3–12s 切片，按任务 embedding 检索）
```

每个 episode 携带 `quality_flags`（拒绝/降级原因码）与 `quality_score`（0–1 合成分）。状态迁移全部落 lineage 表：谁（哪个 worker/模型版本）在何时基于什么规则做了什么决定。

## 1. 清洗（对应五阶段的门①② + QC 三级）

### 1.1 技术门（纯规则，CPU，入湖即跑）

| 检查 | 方法 | 处置 |
|---|---|---|
| 容器/流完整性 | ffprobe 校验、MCAP chunk checksum | 损坏→拒收 |
| 时间戳 | 单调性、跨流对齐残差（视觉↔IMU↔信号流 <1 帧周期）、GoPro 时戳抖动检查 | 超限→reject_timing |
| 时长/帧率 | <10s 拒；fps 波动 >5% 标记 | 拒/降级 |
| 元数据 | 标定文件存在且版本匹配、设备固件版本、传感器健康自检记录 | 缺失→拒收 |
| 隐私 | 人脸检测→模糊（不可逆，唯一的破坏性操作；端上可选先模糊，入湖强制复检并补模糊；误模糊率进 QC 指标，脱敏前的哈希留存以审计）；GPS 等敏感元数据剥离。政策与保留期见 [compliance-and-security.md](compliance-and-security.md) | 强制 |

### 1.2 视觉门（轻量模型，GPU 批处理）

- **清晰度**：Laplacian 方差（快筛）+ 无参考质量模型（MUSIQ/DOVER 类）抽样复核
- **曝光**：直方图裁剪比例（过曝/欠曝像素占比阈值）
- **抖动**：IMU 角速度积分 + 稀疏光流幅值双指标（有 IMU 用 IMU，纯视频用光流）
- **内容有效性**：黑屏/镜头遮挡/朝天花板占比
- **手部可见率**（human/device 轨核心指标）：轻量手部检测器逐秒采样，可见帧占比 <60% → 不拒，**降级路由**到导航/预训练轨道
- 全部指标写入 episode 指标表，阈值集中在 configs/ 可调——阈值最终服从下游消融（§7）。**过渡方案（M2 期消融工具尚未交付时）**：阈值取本文写死的临时值并版本化，各门只做标记不做删除，记录漏斗通过率；M3 mixture-runner 就绪后按 §7 回溯裁决（governance.md U-16）

### 1.3 运动学门（robot/device 轨，L1）

对标 Ego2Robot L1：目标机器人 IK 可行性（人手姿态机器人到不了→标记不可重定向段）、自碰撞检查、速度/加速度/jerk 离群（>99.9 分位截断）、静止段占比（>70% 静止→降级）。

### 1.4 统计门（L2）

与同任务集群比较：轨迹时长/平滑度/工作空间覆盖的分布位置（分位数或 Mahalanobis 距离），尾部 1% 标记人工复核。目的：抓"单条看正常、放进群体看异常"的样本（如速度普遍异常的某台设备=标定坏了）。

### 1.4b 跨模态一致性门（通义双管线补充）

两个我们原设计缺失、通义清洗管线实战验证的门类（见 [research-qwen-robotics.md](research-qwen-robotics.md) §2）：

- **指令-动作一致性检查**：语言标注与实际动作/轨迹是否互相印证（标注说"拿起杯子"但夹爪从未闭合→标记）
- **视频-状态一致性检查**：视觉内容与状态流是否一致（画面手在动但状态流静止→时间错位或传感器故障）

### 1.5 语义审计（VLM，L3，抽样）

- Prompt 三问：视频里做的是不是声明的任务？任务是否实际完成？是否摆拍/无实质操作？
- 抽检率随 Creator 信誉浮动：新账户 100%、高信誉 1–5%
- 输出 `task_match / completed / staged` 三个布尔 + 置信度

### 1.6 反欺诈（账户级，与 episode 级并行）

- 设备指纹 + 时空一致性（同设备不可能同时两地）
- **回放攻击**：屏幕翻拍检测（摩尔纹/边框检测）、同内容跨账户 embedding 碰撞
- 计酬锚定"通过策展分钟数"（激励层防御），人工审核台处理灰区
- Creator 信誉分 = 历史通过率 + 审计结果的指数滑动平均

## 2. 去重与再平衡（门③④）

### 2.1 去重

- **embedding 选型**（以 [cleaning-algo-selection.md](cleaning-algo-selection.md) §1.9 为准）：**SigLIP 帧特征聚合（Apache-2.0）起步**，InternVideo2/VideoMAE V2 类视频级表征在 license 核查通过后升级；向量库存全量
- **两层阈值**：近重复（余弦 >0.95，同机位同任务重复录制）→ 保留质量分最高的 1 条；语义重复（0.85–0.95）→ 不删，参与再平衡降权
- 同人去重严、跨人去重松（跨人的"相似"本身是操作者多样性）

### 2.2 再平衡

- 对 curated 池按（任务 × 物体 × 环境 × 操作者）四轴聚类（前三轴 embedding + HDBSCAN，操作者轴直接用 `operator_id`），统计簇覆盖度——操作者轴依据 Lin 幂律（research-vla-pretraining §4.5：场景×物体×操作者数是要扩的三个维度）
- **多样性 KPI**：每 1,000 小时独特任务/物体/环境/操作者数（前三项对标 Index 373/1,146/116，为公司自报数字且分母口径未公开，见 governance.md D-09；计数定义见 [eval-protocol.md](eval-protocol.md) 指标字典）
- 稀缺簇 → 生成任务配额下发 App（主动采集）；过剩簇 → 采样降权（被动平衡）
- 训练分片构建时按簇做温度采样（稀缺簇过采样），温度是消融参数

## 3. 分割

### 3.1 会话 → episode

起止信号优先级：App 显式标记 > 语音口令（"开始/完成"）> 静止检测兜底（首尾去除无操作段）。

### 3.2 episode → 子任务（技术方向按可靠度排序）

1. **硬件事件锚点**（device/robot 轨首选）：夹爪开合沿、接触力突变——物理事件是最干净的子任务边界
2. **手-物接触事件**（human 轨）：手部关键点与物体检测框的接触/分离时刻
3. **运动学分割**：EE/手部速度极小值点（动作单元之间必减速，经典 motion segmentation）
4. **VLM 时序定位**：给 VLM 整段视频让其输出子任务时间戳（NILS 式集成：多个冻结基础模型投票）——最灵活也最贵，用于校正前三者
- 融合策略：1–3 生成候选边界，4 做语义合并与命名；边界精度要求"秒级"，不追帧级
- 产物：子任务区间表 + 每段一条指令（§4），同时生成演示库切片（3–12s，起止对齐子任务边界）

## 4. 标注加工

### 4.1 分层语言标注（全轨）

- 三级：任务级（整段一句）/ 子任务级（每段一句）/ 操作级（动词短语，可选）
- **事后反推式 prompt**（Figure 原方）："你会给机器人什么指令，才能得到这段视频里的行为？"
- **轨迹投影叠加**（通义技巧）：VLM 标注前把手腕/EE 轨迹投影叠加到采样帧上——VLM 能"看见"运动而不只是静帧，标注质量显著受益
- 一致性防线：双模型交叉标注（Qwen-VL 本地 + Claude API），分歧样本进人工队列；指令与视频 embedding 对齐度检查（CLIP 分数过低→重标）。标注不一致比标注缺失更伤下游（DeMiAn 结论）
- sim 轨 `planning_trace` 例外：子任务区间与完成标签由仿真谓词校验写入（真值），VLM 不重标边界，只做**指令改写**（把模板化谓词任务改写成多样自然语言，保留原模板进 lineage），并用这批真值抽检 §3 分割器与本节标注器的精度
- 存储：JSON 随 episode 元数据，进 LeRobotDataset task 字段

### 4.2 伪标签工厂（human 轨）

流水线（细节与依据见 [index-replica-plan.md](index-replica-plan.md) §4；纯视觉手部位姿的精度保证与 device 轨真值校准见 [device-track-umi.md](device-track-umi.md) §3、[cleaning-algo-selection.md](cleaning-algo-selection.md) §1 手部姿态条目）：

1. 手部关键点（HaMeR/WiLoR 级模型逐帧初值）
2. 整段时序优化：骨长恒定 + 关节限位 + 速度上限约束 + Savitzky-Golay/SLERP 平滑；遮挡帧标插值
3. 相机位姿：VIO/SLAM → 世界系解耦（先解自运动再解手）
4. EE 化 + 逐形态重定向（FK 感知，保持腕/指尖任务空间几何）
5. 中间表征：光流（必做，SOF 证据）、单目深度（可选）
6. **质量分合成** = 模型置信 × 多视角一致 × 时序一致 × 物理合理 × 误差预测器（金标准配对数据训练，device 轨同穿戴数据 + 小规模动捕）

### 4.3 device/robot 轨后处理

SLAM 位姿回环校正与平滑；gripper 宽度标记追踪缺帧插补；robot 轨附加：干预点标记、成功/失败标（奖励分类器素材）。

## 5. 加工成训练态

- **转码**：入湖统一 AV1（svt-av1，硬编优先）+ yuv420p；分辨率阶梯（原始存档 / 训练 448p–720p / 预览 320p）；GOP 对齐子任务边界附近以利随机访问
- **时间对齐与重采样**：分层采样率保持（视觉 ~10–30Hz、信号 100–200Hz），**不做全局重采样**；训练取帧规则：信号流线性插值到查询时刻，视觉流取最近帧并记录 Δt（模型可选消费）
- **归一化统计**：per-dataset per-channel 分位数统计（1%/99% 截断归一化优于 min-max，抗离群）；统计文件随数据集版本走
- **打包**：LeRobotDataset v3（多 episode 合并 parquet + 分 shard mp4 + 关系元数据）；按（track × 任务簇 × 质量分层）组织 shard，支撑流式与消融切分
- **增强不落盘**：颜色抖动/裁剪等在训练 dataloader 做，存储永远保持原样

## 6. 基础设施

- DAG 引擎：消息队列 + 无状态 worker（每阶段幂等、可重放，失败进死信队列）；中间产物（embedding、关键点、光流）全部缓存——重跑策展不重跑感知模型
- GPU 批处理池与 CPU 规则池分离；VLM 调用带预算与降级（本地模型兜底）
- lineage：每个训练分片 → 策展决策 → 原始上传全链路可查；删除请求沿此链传导

## 7. 验收与消融钩子（本文件所有阈值的最终裁判）

- 每个门的通过率进漏斗仪表盘；阈值改动必须走消融：同批数据不同阈值切子集 → 小模型训练 → 仿真基准分。**指标不涨的严格化一律回退**
- 少样本适应基准（1 条演示零梯度 / 5 分钟 10 步微调）作为演示库质量的直接探针
- 伪标签抽检：金标准配对集上的 MPJPE/轨迹 RMSE 回归，算法升级必须先过此关
- 质量分合成公式（§4.2 第 6 步的六因子乘积）本身要验证：以金标准配对集上"质量分 vs 真实误差"的 Spearman 相关为验收，<0.5 则回退到单因子（误差预测器）

## 8. 评测集固定与泄漏防护

- **held-out 在 ingest 后、curation 前就固定**：按 `scene_id` 与 `operator_id` 做组切分（同一场景/同一操作者不跨 train/held-out），比例 5–10%，切分结果写入 `split` 字段并版本化（`split_version`）；曾进入 held-out 的 episode 永不回流训练集
- **M1 期（curation 尚未实现）的过渡**：Stage A 微调验证前，export 层用同一组切分规则生成 held-out 清单文件（`data/splits/<version>.json`）——机制不等 M2
- 去重与再平衡只在 train 池内做，held-out 不参与聚类统计；演示库切片不得取自 held-out episode
- 泄漏检测：训练前跑 train↔held-out 的近重复检查（余弦 >0.95 视为泄漏，直接从 train 剔除并记录）
- 真机评测任务集与仿真基准的选定、统计判定规则见 [eval-protocol.md](eval-protocol.md)

## 9. 人工在环（HITL）

- 人工触点只有四个：欺诈灰区审核台（§1.6）、L2 尾部 1% 复核（§1.4）、VLM 双模型分歧队列（§4.1）、伪标签金标准抽检（§7）；其余全自动
- 编制估算（H1 规模，1,000 小时/月入湖）：欺诈灰区约 2–3% 上传 → 2 人；L2 尾部 1% + 分歧样本 <5% → 2 人；金标准抽检 1 人；共 5 人/千小时·月，随信誉体系成熟下降。成本进 [program-plan.md](program-plan.md) 预算
- 审核台产物（标签、裁决）全部进 lineage，作为 VLM 审计与欺诈模型的再训练数据；审核员一致性（Cohen's κ）每月抽测，<0.7 重训指南
- 隐私：审核员只看脱敏后（人脸已模糊）的预览流，raw 不进审核台
