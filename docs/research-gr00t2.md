## 0. 结论

1. **GR00T 2 是一个 WAM，不是 VLA。** 一个 2B 的扩散 transformer，从 Cosmos-Predict2.5-2B 视频模型初始化，**同时**对多路相机的未来视频和一段动作块去噪。动作 token 会注意到正在生成的未来帧，所以动作是“跟着想象出来的未来走的”（[N:wp] §2）。和 GR00T N1/N1.7（Eagle VLM + DiT 动作头）相比是路线切换。
2. **它可以用没有动作标签的人类视频做预训练。** 人类视频的监督信号来自两部分：视频预测损失，以及有手部位姿时的动作损失。原因是视频损失对所有数据源都成立。混合数据量如下（[N:wp] §4.2）：
   - **402,730 h** 第一视角人类视频；
   - **10,184 h** UMI 手持夹爪；
   - **23,500 h** 遥操作。

   人类视频从 0 增加到 100%，真机新任务成功率从 18% 到 41%，到 100% 仍未饱和（⚠️ 自报，单次训练）。
3. **“X-Adapt”的数据配方**：目标机器人只提供**与任务无关的 play 数据**（交代“这台机器长什么样、怎么动”），任务演示全部来自人、UMI 或 DexUMI。DexUMI 外骨骼和机器人手关节一一对应，因此连 play 数据都不需要（[N:wp] §4.4）。这是“采集器与执行端共同设计”的一手正面证据。
4. **数据管线有四点和我们的设计直接相关：**
   - **(a) QC 是离线计算的“样本起点视图”，不在加载路径上过滤。** QC 信号按训练样本实际读取的时间窗求值，新增 QC 列不重写旧数据。
   - **(b) 存储用 Lance 列式格式 + 快照版本。** 训练运行钉死每个数据集的快照，归一化统计跟着视图走。
   - **(c) 标注用自研 Flora 三模型（切分 / 描述 / 奖励）**，重标约 40 万小时人类视频约需两天。
   - **(d) 评测用盲测 A/B + Bradley-Terry Elo（GearArena）**，再用标定过的仿真做代理（Pearson 0.93）。

   详见 §4、§6。
5. **对本仓库**：不改贯穿性决策。最值得吸收的有四条：
   - QC 视图化；
   - in-lab 人类采集协议的量化验收表；
   - UMI 三级 QC；
   - 盲测 A/B 评测法。

   每具身独立 MLP 头仍然保留，说明 [training-pipeline.md](training-pipeline.md) 观察名单里“GR00T N2 若改统一动作空间则重新评估”的触发条件**没有发生**。GR00T 2 自己也承认“各数据源之间的汇率未知”（[N:wp] §5），这和 U-40 的换算率实验是同一个问题，外部没有现成答案。

## 1. 模型工作方式

### 1.1 输入与输出

| 项 | 内容 | 出处 |
|---|---|---|
| 视觉输入 | 最多 4 路相机（通常头部 1 + 双腕 2），**224×320，5 fps，0.8 s 历史** | [N:wp] §2 |
| 本体输入 | 机器人本体状态（proprio） | 同上 |
| 语言输入 | 自然语言指令 | 同上 |
| 输出 | 一个**动作块** + **每路相机的未来帧** | 同上 |
| 执行方式 | 机器人用自己的控制器执行动作块，同时计算下一块（异步，见 §1.4） | [N:wp] §2、§4.6 |

以 Dexter 双臂 + Sharpa 手为例：数据 30 Hz；状态 62 维，为机器人基座系下的绝对腕位姿加手关节位置；动作 62 维，为**相对当前状态的腕位姿**加**绝对手关节位置**（[N:wp] B.1.3）。

### 1.2 架构

```
 多路相机历史帧 ──► Wan 2.1 VAE（冻结，时间 4×、空间 8×/维压缩）──► 每帧每路 280 token + 视角嵌入 ─┐
 指令 ───────────► Cosmos-Reason1 VLM（冻结）──► cross-attention ──────────────────────────────┤
 本体状态 / 加噪动作块 ──► 每具身独立的小 MLP 编码器 ──────────────────────────────────────────┤
                                                                                             ▼
                         单个 2B DiT（Cosmos-Predict2.5-2B 初始化），一条 token 序列
                         · 视频 token：跨时间、跨相机互相注意
                         · 动作 token：注意全部视频 token（含正在生成的未来帧）
                                                                                             │
                         ┌──────────────────────────────────────┬────────────────────────────┘
                         ▼                                      ▼
                未来视频 latent（flow matching 损失）    每具身独立解码器 → 动作块（flow matching 损失）
```

- **训练目标**：视频和动作各一项 flow matching 损失；动作损失只在有有效动作监督时才计（[N:wp] §2、§4.1）。
- **去噪步数**：部署时视频 1–2 步、动作 2–4 步（[N:wp] §2）。在 G1 上调到“1 步视频 + 2 步动作”（[N:wp] §4.6.1 图 19）。
- **每具身独立的状态/动作 MLP**：新机器人接入要做三件事（[N:wp] §2）：
  1. 把相机映射到头部和腕部视角；
  2. 把动作表达成某个已支持的动作空间，或者新加一个；
  3. 用目标任务演示做后训练。

  加载时由 recipe 里的 **embodiment tag** 选出对应的状态/动作分组、相机、标注、归一化统计和投影层（[N:wp] §4.7.2）。

### 1.3 GR00T 2 Turbo（端侧版）

- transformer 仍是 2B。视频 VAE 换成 Wan 2.2，空间压缩从 8× 提到 16×/维，latent 网格缩小 4 倍，动作时长不变（[N:wp] §2）。
- 延迟（⚠️ 自报）：
  - G1 预测：RTX 5090 上 38 ms，Jetson Thor 机载 124 ms；约每秒规划一次 1.6 s 的全身运动 latent，交给 SONIC 以 50 Hz 执行，G1 关节 PD 控制为 1 kHz（[N:page]、[N:wp] §4.6.1）。
  - YAM 上和完整版在统计上没有区别，单次推理 52 ms 对 171 ms（[N:wp] §4.3）。
- **代价**：后训练后灵巧手任务成功率从 68.6% 掉到 34.3%，YAM 只掉 6.7 个点（[N:wp] §5）。NVIDIA 自己的解读是：“需要预测多少视觉细节，取决于任务和本体”。

### 1.4 推理与部署

- 客户端-服务端结构：客户端发相机历史、状态和指令，服务端返回动作块；客户端缓冲后按控制器频率执行，同时请求下一块。
- 服务端做了这些加速：
  - 指令不变时复用文本特征；
  - 只做动作去噪的步骤复用最近一次视频步的 KV；
  - TensorRT + CUDA graph；
  - 部分层用 FP8；
  - 减少去噪步数。

  合计中位延迟降到原来的 1/2.9–1/7.2（[N:wp] §4.6.1）。
- **带噪前缀 RTC**：微调时给已提交动作前缀加高斯噪声，推理时用干净前缀。用干净前缀训练反而在短延迟下掉成功率（[N:wp] §4.6.2）。
- **按阶段变速**：一个子任务预测器标出动作块所处的阶段（抓、运、拧……），按 agent 搜出来的逐阶段速度表重定时，让执行速度超过示范速度（[N:wp] §4.6.3）。

### 1.5 Agent 接口（WAM API）

前沿推理模型担任 System 2，做“观察-推理-执行-验证”循环，把 GR00T 2 当工具调用。两种接法：

- **控制**：agent 拆步骤、检查进度，卡住时调用 code-as-policy 恢复技能（[N:page]、[N:wp] §1）。
- **视觉引导**：agent 在 GR00T 2 的相机画面上标抓取点和释放点，按手臂区分颜色。**训练不需要新数据**：这些标记从现有演示的夹爪/手状态里自动抽取（[N:page]）。

## 2. 训练流程

| 阶段 | 数据 | 目标 | 出处 |
|---|---|---|---|
| Stage 1 单视角视频预训练 | 第一视角人类视频为主，辅以机器人数据，单路相机 | 只做未来视频预测，先建立“具身交互的视觉动力学先验” | [N:wp] §4.1 |
| Stage 2 多视角视频-动作联训 | 人 + 机器人，有多视角就用多视角；人类视频以跟踪到的手部位姿作动作监督 | 视频与动作联合 flow matching，接入每具身 MLP；提高 YAM 与灵巧手占比，保留大量人类视频 | 同上 |
| Stage 3 机器人加权联训 | 同上，加大机器人（尤其 YAM）权重 | 把模型拉回机器人自身的动作空间 | 同上 |
| 后训练 / 少样本适配 | 每任务少量演示；约 6 个 epoch | 5 条演示（少于 3 分钟机器人数据）+ 单卡 RTX 5090 上 30 分钟 LoRA：Dexter-50 成功率 40% → 95% ⚠️ | [N:page]、[N:wp] §3.1 |
| RL 后训练 | 真机 / 神经仿真（DreamDojo 世界模型）| 只在动作去噪注入噪声（CPS），视频去噪保持确定性；GRPO 式组相对目标，baseline 记住每个上下文的历史回报；另有 GRPO 诱导自模仿、残差 RL | [N:wp] §4.1、§4.5.3 |

算力：主预训练用 GB300 NVL72 集群（共 2,016 卡）中的 **1,024 卡**，DeepSpeed ZeRO-2 纯数据并行，每卡 batch 16，不用流水并行（[N:wp] §4.7.1）。总训练时长、token 数、GPU·时**未披露**。

| 源 | 平台 | episode | 小时 | 采样份额 |
|---|---|---|---|---|

**人类视频缩放消融**（[N:wp] §4.2.1、C.1.5，⚠️ 自报）：
- 设置：人类视频取 0% / 1% / 10% / 100%，过滤后分别为 0 / 0.87k / 8.1k / 84.4k h；Dexter 遥操数据固定，训 3 个 epoch，采样配比 Dexter 45% / 人类 55%。
- 评测：72 个任务，每任务 3 次。
- 结果：真机成功率 18 / 27 / 28 / 41%，任务进度 50 / 58 / 61 / 70%；每增加 10 倍人类视频，真机进度约 +6 个点。
- **局限**：每个份额只训一次，误差棒只反映 rollout 方差，不反映训练方差；1% 到 10% 这一步在真机上处于噪声范围内。

## 4. 数据管线（采集 → 质检 → 标注 → 处理 → 存储加载 → 评测）

### 4.1 人类视频：采集规范与两级质检

**数据形态**（[N:wp] C.1.1、[N:h1m]）：
- 视觉：单目或双目头部 RGB，部分加腕部相机。
- 每 episode 的标注：
  - 头部相机 6-DoF 位姿（SLAM，每 episode 一个规范世界系）；
  - 每只手 21 个 3D 关键点（米制、头部相机系、逐帧对齐，带跟踪掩码与置信度）；
  - 两级语言标注：**T1** 为 1–2 句 episode 摘要；**T2** 为连续的 1–10 s 时间段，每段写明哪只手、动作和物体，可脱离上下文单独理解。
- 数据卡对 episode 的要求（[N:h1m]）：
  - 至少 30 fps / 480p，不变速；
  - 一只或多只手在画面中的时间不少于 95%；
  - 一个 episode 通常 5–10 分钟，有明确可测的目标。

**两级质检**（[N:wp] C.1.2）：
1. **批次级人工审核**：检查语言标注是否有效、任务质量、空闲时长，按 episode 计通过率要求 95%。
2. **逐时间步量化过滤**：对每个候选训练时间步，取**过去 24 帧 + 未来 48 帧**的窗口，窗口内全部通过才保留（表 8）：

| 信号 | 窗口统计 | 接受条件 |
|---|---|---|
| 头部角速度 | 均值 | ≤ 20°/s |
| 头部平移速度 | 均值 | ≤ 0.2 m/s |
| 手骨长误差（20 根指骨长与 episode 中位数的 MAD / 均值） | 最大 | ≤ 0.05 |
| 手可见性 | 最小 | 双手都在画面内 |
| 腕速度 | 最大 | ≤ 1.0 m/s |

**in-lab 机器人对齐采集**（[N:wp] C.1.3–C.1.4，studio 规范 v1.3.2）。要缩小的有两类差距：
- **观测差距**：腕部相机摆位不同，手看起来的角度、尺度、位置都不一样；
- **动作差距**：人比遥操快，有停顿和无关动作，有些动作机器人手做不出来。

验收表（表 9）：

| 项 | 要求 |
|---|---|
| 头部 | 稳定，不转动 |
| 手可见 | 双手 100% 帧可见 |
| 空闲 | 无（允许短暂的任务相关检视） |
| 腕速度 | ≥0.40 m/s 的样本 <5%，≤60% 的样本低于 0.03 m/s，跟随参考视频节奏 |
| 腕部相机 | 4.4 cm 标定块在机器人视角中尺度为 0.8–1.2×；手臂伸直时人手与机器人手 IoU > 0.5 |
| 手位姿质量 | 按速度分档的抖动 ≤ 机器人参考的 4×，有逐帧置信度，重投影抽查 |
| 演示数 | 每任务 400 条：8 个环境 × 50 条 |
| 物体 | 与机器人配对的任务用指定 SKU，或 3 个形状尺寸相近的变体 |
| 交付物 | 头部与腕部内参、双目外参、每批次的腕速度统计 |

腕部相机支架的设计过程：13 种初始设计，选 4 种 × 4 名操作员做受控对比，比较手物重叠、物体尺度、相机到物体距离和相机朝向，最后用 ChArUco 加方向性动作优化角度对齐（[N:wp] C.1.1）。

### 4.2 UMI-10K：任务生成 + 三级质检

- **任务生成**：一个基于语言模型的 agent 把 49 技能词表里的技能和物体库配对，填进任务模板；模板经过 lint，并和所有已有任务去重，再由人工逐条接受或拒绝。每个模板实例化时随机采样物体、数量、颜色、位置，从而产生**反事实对**：同一场景，指令只差一个属性，用来练指令跟随。每轮生成时对已经常见的技能欠采样（[N:wp] C.2）。
- **覆盖**：2,798 个技能-物体组合；top-24 技能 × top-30 物体的网格填满 70%。88% 的 episode 含 pick-and-place 以外的技能，动态技能占 29%，铰接物体 29%，可形变物体 15%，精密技能 17%。
- **三级质检**（[N:wp] C.2），合计滤掉约四分之一的录制：
  1. **采集站侧自动检查**（滤掉约 11%）：帧时序不均、丢帧、跟踪或夹爪故障，当场拒绝；
  2. **agent 质检**（约 16%）：从视频和指令出发，对四个方面打分——任务完成、动作质量（无微调、抖动、犹豫）、场景有效性、视角质量；出现任一致命失败或低分即拒绝；
  3. **人工审计**：抽样复核 agent 的判决，并复核有争议的样本，用金标准集校验，纠错结果回灌到 judge 模型。

### 4.3 遥操作系统（in-lab，Tianji + Sharpa）

- **设备**：PICO、Manus、Sharpa 外骨骼、Quest Pro，统一接入 Isaac Teleop。
- **重定向**：使用与人类数据转换**同一个**闭式 IK 解算器，每秒约 11.8 万次双手求解。
- **硬件**：开源 3-DoF 颈部（GEAR Neck），60 fps 双目头部相机；Televiz 做 3-DoF 重投影，消除头动带来的晕动。
- **用途**：主要服务后训练，也采集与任务无关的 play 数据（[N:wp] C.3.1）。

### 4.4 无遥操作的转换管线（X-Adapt 的数据侧）

| 源 | 采集 | 转换 | 目标机器人需要什么 | 出处 |
|---|---|---|---|---|
| 人类动捕 | 头部 + 腕部相机装在与机器人对齐的位置，Manus 手套，PICO 腕部 6-DoF 跟踪；60 Hz 原始流 | 腕位姿锚定到重力对齐的机器人基座系（绝对位姿），手指按指尖目标做 IK 重定向；**视频不改**；降采样到 30 Hz，得到与真机相同的 schema | 与任务无关的 play 数据，后训练时 1:1 混采 | [N:wp] §4.4.1、B.1.2–B.1.3 |
| Gripper UMI → YAM | GEAR UMI（开源），腕部相机 + 开合编码器 | 鱼眼腕部画面重渲染成 YAM 腕部相机的样子（模型“吸收外观、不吸收几何”）；动作重新表达到 YAM 动作空间，由 YAM 的动作头解码 | YAM play 数据；每任务 41–75 条 UMI 演示可达高成功率，由最稀有的子技能决定 | [N:wp] §4.4.2 |
| DexUMI → XHAND | GEAR DexUMI 外骨骼，16 DoF 与 XHAND1 Pro-U 一一对应，接触面、腕部相机安装位、触觉格式都对齐 | 绿色部件按颜色分割，在条件帧和预测帧里**一致地随机化外观**，取代以前“回放到机器人手上再 inpaint”的步骤；指尖力投影成关节力矩并入动作，执行时用来调刚度 | **不需要 play 数据** | [N:wp] §4.4.3 |
| DexUMI → Sharpa | 同上 | 由关节角算 XHAND 指尖位置，再用同一闭式解算器重定向到 22-DoF Sharpa；腕部画面做 warp；45 Hz 重采样到 30 Hz，打上 Sharpa 的 embodiment tag | Sharpa play 数据 | [N:wp] §4.4.3、B.4 |
| 人 → 仿真 → 真机 | 单条人类视频 | NVIDIA Video to Data 重建物体和手物运动；状态型 RL 专家（CHORD）跟踪轨迹；rollout 加随机动作扰动与瞬移，以包含纠错行为；在 Isaac Lab 中随机外观、光照、相机标定后渲染；每任务 1.5k episode | 无真机数据，零样本上真机 | [N:wp] §4.4.4 |

NVIDIA 的结论（[N:wp] §5）：**“演示负责交代任务，目标机器人的 play 数据负责交代本体”**；以及“应当共同设计机器人和采集设备，共享运动学、相机位置和触觉格式”。

### 4.5 标注：Flora 数据引擎

三个模型（[N:wp] §4.2.4、C.4）：

| 模型 | 作用 | 训练 |
|---|---|---|
| Flora-TempSeg | 在重叠窗口上预测每个动作的起止时间，并标出越过窗口边界的动作，再拼接成 episode 级区间；并发动作（两只手做不同事）保持为独立区间 | 先在人工标注上 SFT，再用 GRPO 训练，可验证奖励为时间 F1 和边界精度 |
| Flora-Captioner | 对每个区间单独写描述，同时看前后相邻动作的帧以确定物体身份和意图；多视角逐时间步拼成一张图；输出自包含的祈使句（如 “hold tea leaves with right hand, pass tea leaves to left hand”）；**失败尝试按意图描述，不暗示成功** | SFT 后用 GRPO 训练，奖励为对参考要求的覆盖度，事实错误扣分 |
| Flora-Rewarder | 产出结果奖励、稠密奖励、rubric 奖励，供 RL 与评测使用 | 未详述 |

- **用途**：预训练的语言条件、过滤与再平衡；RL 的过程奖励；评测的结果标注。
- **效果与成本**（⚠️ 自报）：WGO-Bench 时间切分 F1 为 50.3，次优为 GPT-6 Astra 的 46.0；重标约 40 万小时 Human-1M 约需两天。人类视频的 T2 标注先由人工 QC 筛出最优样本训练 Flora，再由 Flora 补全全量（[N:wp] C.1.1）。

### 4.6 多模态处理管线（原始录制 → 训练分片）

（[N:wp] §4.7.3、K.6）
- **规模**：每月 PB 级输入，单个生产作业接近 1 万 vCPU，用 Ray 分出加载、转换、发布三个独立 worker 池。
- **要解决的问题**：转换任务共享输入，又争抢有限的本地存储。一段长视频可能切出多个 episode，一个 episode 又依赖多个相机文件和单独存放的动作记录。共享输入只能等最慢的消费者完成后才能回收，慢任务会堵住无关输入的下载。
- **做法**：
  - 文件从对象存储**直接流式传到处理节点**，不经共享文件系统中转；
  - 按节点存储预算**准入**新输入，预算计入驻留文件、在途传输和输出余量；
  - 把任务派发到持有输入的节点；
  - 一个 episode 的输出**上传完成后才释放**对输入的占用，由消费者完成情况决定新输入何时进入，而不是由预取驱动；
  - 中断后，丢失的输入走同一准入路径重建；转换组和发布各自有持久化 checkpoint，可以复用已完成的结果。
- **生产数据**（⚠️ 自报）：100 节点 × 96 vCPU 的作业，每小时处理 722–780 小时示范数据；第一个训练分片 ≤28 分钟产出；CPU 利用率 97.8%；中断后 92.4% 的已完成转换时间不需重做，重启后 2.4–5.3 分钟恢复发布。

### 4.7 存储与训练加载：LanceDS

（[N:wp] §4.7.2）
- **表结构**：每个数据集有三张表：
  - **step 表**：状态、动作、标注、**QC 信号**；
  - **episode 表**；
  - **media 表**：原始视频。
- **版本**：加 episode、改标注或 QC 时，Lance 保留旧快照；**新增 QC 列不重写已有列**。一次训练运行对每个数据集钉住一个快照，数据、归一化统计和元数据一起可复现。
- **统一 schema**：所有数据集共用一个 schema，读取时由 embodiment tag 选出各具身的字段组。
- **QC 不在加载路径上执行**：QC 规则离线地在“每个训练样本实际读取的时间窗（观测 + 动作目标）”上求值，结果存成“合格样本起点”的**视图**。每个新快照重建视图，视图带有只在保留样本上算出的归一化统计。
- **采样**：每个 rank 用确定性种子按需抽样，混合各分片，使每个全局 step 都符合 recipe 规定的数据集比例。
- **加载流水**（三级异步）：视频分片预取到节点本地 NVMe → 解码（在三视角基准中约占准备时间的 90%）→ 增强、整理、拷入 GPU；变长 token 打包，32,768 token 的行填充率 94.5%。
- **实测**：1,024 卡、25 个数据集、1,560 万 episode、462 亿时间步的规模下，每秒约 1.2 万个样本窗口，平均输入等待 0.37 ms，占步长时间 0.049% ⚠️。
- 加载器的改动先在闭环仿真里验证，再上预训练。

### 4.8 评测：GearArena 与仿真代理

- **为什么用盲测 A/B**：绝对成功率会随采集站、操作员、硬件和日期漂移，不同场次不可比。做法是同场景、同操作员、几分钟内随机顺序跑 2–4 个 checkpoint，让漂移相互抵消。所有对比合起来拟合 Bradley-Terry Elo；每个任务等权；置信区间按**任务**重采样 bootstrap，不按试次。新 checkpoint 先和榜首参考对打，保证所有评分在同一尺度上（[N:wp] §4.3）。
- **规模**：195 场 campaign、16,044 条打分 episode、11,767 次成对比较、10 个 YAM 站、20+ 名操作员、71 个 checkpoint（2026-07 至 11 月）。
- **任务设计**：所有 checkpoint 都能完成的任务归档，都完成不了的搁置，因为两者都不区分模型。
- **结果**（⚠️ 自报）：GR00T 2 比 π0.5 高 236 Elo，期望胜率 80%；比 GR00T 1.7 高 95 Elo。
- **仿真代理**（[N:wp] §4.5）：
  - 用 agent 辅助的 real-to-sim 流程，基于 SimFoundry 工具、Isaac Lab Arena、Newton 和 MuJoCo Warp，重建 25 个 YAM 任务。
  - 14 个 checkpoint 的仿真与真机对比：任务进度 Pearson 0.93，成功率 0.92，Elo 0.93。
  - 用途：缩小最终候选范围（3 个再上真机）；在仿真里先测序列打包、混合分片采样这类**数据管线改动**；在仿真里筛推理设置。
- **NVIDIA 自己承认的局限**（[N:wp] §5）：
  - 每任务 ≤20 次试验，只够分辨大差距；区分 95% 和 99% 每个策略约需 285 次；
  - 30–35% 的对比是平局；
  - 拧到一半的螺丝被模型和 agent 都判为完成（自动验证的难点）。
