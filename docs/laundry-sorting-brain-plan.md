# 脏衣服分类：识别与决策"大脑"的训练详细计划

> 2026-09-20。对应 [laundry-two-plans-brief.md](laundry-two-plans-brief.md) 的步骤 A1（脏衣服分类）与 A4（VLM 大脑 v1），按"交付一 3 个月加速版"（该文 §8.1）排期。本体：自研轮式人形，头部 RealSense D457、腕部 D405 × 2、二指力控夹爪、机载 Jetson Thor（[具身档案](../configs/embodiments/inhouse_wheeled_humanoid_v1.yaml)）。**金额、算力、样本量、准确率目标均为我方估算或设计目标 ⚠️，不是已验证结果；公开数据集与洗标标准的许可 / 适用地区均未核查，列为第 1 周任务。**

## 0. 结论先说

1. **不要用一个 VLM 包办。** 分类是"错一次就赔钱"的任务（深色混进白色、羊毛进了烘干机），需要的是可校准的置信度和"拿不准就放人工筐"的能力。方案是三层：**视觉前端（分割 + 找抓取点）→ VLM 做属性识别与洗标阅读 → 规则引擎做分筐决策**。VLM 只输出结构化属性，不直接决定进哪个筐。
2. **VLM 不进 10 Hz 控制回路。** 每件衣服触发一次识别，预算 2–3 秒 / 件；不常驻占用 Thor，给动作模型让出算力。
3. **真正难的不是"这是什么衣服"，而是两件事**：从视觉判断面料（羊毛针织和腈纶针织看起来几乎一样）、以及洗标往往藏在领口或侧缝里机器人翻不到。对策是保守策略 + 主动感知（换面、凑近腕部相机）+ 弃权进人工筐，而不是追求视觉上分清一切。
4. 12 周计划：第 1 周零样本基线定出"哪些属性已经解决"；第 4 周分类判别 ≥90%；第 12 周错分率 ≤5%、弃权率 ≤15%；第 5 个月错分率 ≤3%。
5. 需要的数据：**自采 2,000 件 / 约 2 万张起步，第 12 周到 8,000 件**；人读洗标作为金标准。预算已含在汇报稿 A1 + A4 两步内（合计约 $88–167k），不需追加。

## 1. 任务定义

### 1.1 业务流程里的位置

```
客户订单袋 → 倒入分拣台（订单隔离，一次只处理一个订单）
  → ① 衣堆分割，选最上层一件，给抓取点           [视觉前端，每次抓取]
  → ② 机器人单件抓起，举到"展示位"                [动作模型]
  → ③ 头部相机多视角 + 腕部相机近拍 → 属性识别     [VLM，2–3 s]
  → ④ 置信度不足：换面 / 凑近 / 重抓，最多 2 次     [主动感知]
  → ⑤ 规则引擎：属性 → 分筐；拿不准 → 人工筐       [规则，版本化]
  → ⑥ 放入对应筐；决策全程记录                     [动作模型 + 日志]
```

**订单隔离是硬约束**：洗衣房按客户订单洗，不同客户的衣物不能混。每次识别与分筐记录都带 `order_id`；分筐是在一个订单内部分出浅 / 深 / 精细等。

### 1.2 VLM 的输出（结构化，不是自由文本）

| 字段 | 取值 | 说明 |
|---|---|---|
| `garment_type` | T 恤 / 衬衫 / 裤 / 牛仔 / 毛衣针织 / 外套 / 内衣 / 袜 / 毛巾 / 床品 / 其他 / 未知 | 决定后续折法，也影响洗涤程序 |
| `color_group` | 白 / 浅 / 深 / 鲜艳易掉色 / 多色拼接 / 未知 | 分筐的主维度 |
| `fabric_class` | 棉麻 / 化纤 / 牛仔 / 羊毛羊绒 / 丝与蕾丝等精细 / 羽绒 / 未知 | 视觉判断不可靠，默认允许"未知" |
| `care_label` | `visible: bool`；`wash_max_temp`、`hand_wash`、`no_tumble_dry`、`dry_clean_only`、`no_bleach`；`fiber_text` | 只有拍到洗标时才填；洗标优先级高于视觉判断 |
| `attention` | 口袋有物 / 拉链未拉 / 带金属装饰 / 严重污渍 / 破损 | 触发人工或预处理 |
| `confidence` | 每个字段一个 0–1 | 经校准后使用（§4 的 S5 阶段） |

### 1.3 分筐规则（规则引擎，不训练）

| 优先级 | 条件 | 去向 |
|---|---|---|
| 1 | `dry_clean_only` 或 `fabric_class` ∈ {羊毛羊绒、丝与精细、羽绒} 或任何 `attention` | **人工筐** |
| 2 | 任一关键字段（`color_group`、`fabric_class`）校准后置信度低于阈值，且主动感知 2 次后仍不足 | **人工筐** |
| 3 | `hand_wash` | 精细 / 手洗筐 |
| 4 | `color_group` = 鲜艳易掉色 或 新牛仔 | 深色单独筐 |
| 5 | 白 / 浅 / 深 | 对应筐 |
| 3.5 | `no_tumble_dry` | **"不可烘"筐**（单独成锅或装网袋）。衣物进洗衣机后身份丢失，洗后无法再挑出，所以必须洗前分开；洗后整筐交人工晾（交付一）或晾挂流程（交付二） |

筐数与合并规则按站点配置：很多代洗店按订单整锅洗、只分深浅，小订单拆成多个小锅会压低洗衣机利用率，**第 1 周向试点方确认现行做法后定分筐方案 v1**（governance U-42）。"易掉色""新牛仔"不是视觉属性，规则按保守口径执行：高饱和红、深蓝、深色牛仔一律进深色单独筐，不让模型判断色牢度。

规则存 `configs/laundry/sort_policy_v1.yaml`，改动即新版本；不同洗衣房可以有自己的规则版本，模型不用重训。

## 2. 三层结构与选型

| 层 | 做什么 | 选型 | 备注 |
|---|---|---|---|
| L1 视觉前端 | 衣堆实例分割，选最上层、遮挡最少的一件，输出抓取点候选 | SAM2 + D457 深度（SAM2 与本地 Qwen-VL 在仓库默认路径资产清单内，data-strategy-roadmap §3 L5） | 不需要知道"是什么"，只要"哪一件在最上面"；抓起后判"是否只抓了一件"用三者合判：夹爪闭合开度（布层厚度）、提起重量（关节电流差，A0 标定）、展示位轮廓；夹持力本身不反映件数 |
| L2 属性识别 | 展示位 2–3 个视角 + 腕部近拍 → §1.2 的 JSON | 开放权重 VLM：Thor 上跑 4B 级量化版；站点服务器可用 8B 级；训练时用 32B 级或商用 API 当教师 | LoRA 微调；同时训一个轻量分类头（冻结视觉编码器上的线性探针）做 `color_group` 与 `garment_type` 的快速通道和交叉校验 |
| L3 洗标阅读 | 洗标可见时：定位 → 符号识别 + 成分文字 OCR | 同一个 VLM 加专项数据；符号集按试点所在地标准确定 | 各地区洗标标准不同（ISO 3758 / GINETEX、美国 ASTM、台湾与大陆各有国标）⚠️ 待核；符号是标准化图形，可大量合成 |
| 决策 | 属性 + 置信度 → 分筐 | 规则引擎（§1.3） | 不用模型决策，便于审计与客户定制 |

为什么 L2 要"VLM + 小分类头"两路：两路不一致本身就是很好的低置信度信号，比单模型的自报置信度可靠；颜色分组这类简单属性小分类头更快更稳，VLM 的价值在洗标、异常情况和长尾衣物。

## 3. 数据计划

### 3.1 来源与数量

| 来源 | 内容 | 数量 | 用途 | 状态 |
|---|---|---|---|---|
| **自采（主力）** | 训练用：按公斤采购的二手衣物（第 1 周到位，可随意弄湿弄脏）+ 内部洗衣服务的员工衣物；测试集只用真实订单衣物。采集台拍摄：衣堆俯视、展示位 3 视角（头部相机）、腕部近拍 2 张（面料纹理、洗标） | 第 3 周 2,000 件 ≈ 2 万张；第 12 周 8,000 件 ≈ 8 万张 | 训练 + 评测 | 第 1 周搭采集台 |
| 人读洗标金标准 | 标注员翻出每件衣物的洗标，录入符号与成分 | 与自采同件数 | `fabric_class`、`care_label` 的真值——**不靠看图猜面料** | 同上 |
| 状态变化 | 同一件衣物的干 / 湿 / 皱 / 反面 / 局部污渍；三种光照 | 每件 2–3 个状态 | 鲁棒性；洗后湿衣的颜色偏深是已知问题 | 同上 |
| 合成洗标 | 标准符号 × 字体 × 布料底纹 × 褶皱、模糊、反光增强 | 5–10 万张 | L3 预训练 | 第 2 周 |
| 公开服装数据集 | 服装类别与属性 | 视许可而定 | 只作类别先验的补充；**许可未核查 ⚠️，核查前仅研究分支**（CLAUDE.md 约定） | 第 1 周核查 |
| 部署回流 | 人工筐里的每一件、客户投诉的每一单、主动感知重试的样本 | 持续 | 每周难例集 | 交付一 a 之后 |

### 3.2 标注流程

1. 教师模型（32B 级或商用 API）给全部图片预标注。
2. 小分类头、教师、学生三方不一致的样本，以及全部 `fabric_class` / `care_label` 字段，进人工复核；其余抽检 10%。仓库原则：VLM 只做预标注与分歧仲裁，不当真值（governance D-13：WGO-Bench 上 VLM 子任务标注端到端 F1 仅 0.168，供应商单家自报 ⚠️）。
3. 标注员 3–5 人；配 1 名洗衣房有经验的师傅每周半天，定"易掉色""需手洗"这类经验性判断的口径——这部分知识不在任何公开数据里。
4. 标注规范、属性本体、规则表三者同版本号管理。

### 3.3 划分与泄漏防护

- **按衣物实例划分**，同一件衣物的所有照片只能在训练集或测试集之一；再按客户订单与采集日期做第二层隔离。
- 测试集 ≥1,000 件（要在 3% 错分率上得到 ±1% 的置信区间，至少需要这个量级），其中刻意过采样高代价类别：新牛仔、红色与深色棉、白底印花、针织、蕾丝。
- 另留一个"新站点测试集"（换一家洗衣房采 300 件），只用于验收，不参与任何调参。

### 3.4 隐私与合规

衣物本身一般不是个人资料，但口袋物品、绣名、工牌会入镜；采集台背景固定、不拍人；订单号做假名化；试点洗衣房的客户告知写进服务条款（compliance-and-security）。

## 4. 训练计划

| 阶段 | 周 | 内容 | 产出与判据 |
|---|---|---|---|
| **S0 零样本基线** | 1 | 300 件金标准集；4B / 8B / 32B 开放权重 VLM 与一个商用 API 纯提示词对比；逐属性出准确率 | 知道"哪些属性已经解决"。预期衣物类型与颜色分组零样本即可较高，面料与洗标明显不足——以实测为准，据此分配后续标注预算 |
| **S1 采集与预标注** | 1–3 | 采集台、标注工具、教师预标注、人工复核流程跑通 | 2,000 件入库；标注一致性（双人复核 κ）≥0.8 |
| **S2 L1 视觉前端** | 2–4 | SAM2 + 深度的最上层实例选择；抓取点候选；开度 + 重量 + 轮廓合判"单件" | 衣堆单件抓取成功率 ≥85%（第 4 周检查点） |
| **S3 属性识别 SFT** | 3–6 | 8B 教师级模型 LoRA 微调 → 蒸馏到 4B；多图输入；结构化 JSON 输出；显式"未知"类；高代价混淆加权 | 第 4 周：分筐判别准确率 ≥90%；第 6 周：≥94% |
| **S4 洗标模块** | 3–7 | 合成数据预训练 → 真实洗标微调；符号逐项精确匹配 + 成分 OCR | 洗标可见时，关键四项（手洗、不可烘、干洗、最高水温）逐项准确率 ≥95% |
| **S5 校准与弃权** | 6–8 | 留出集上做温度缩放；VLM 与小分类头一致性作为特征；按代价矩阵选阈值 | 在弃权率 ≤15% 下，错分率 ≤5%；**高代价错分**（深 / 艳 → 白浅筐，精细 → 普通筐）≤1% |
| **S6 主动感知闭环** | 7–10 | 低置信度 → 换面、凑近腕部相机、重抓；最多 2 次；与动作模型联调 | 主动感知使弃权率下降 ≥1/3，单件平均耗时增加 ≤3 s |
| **S7 部署** | 8–11 | 4B 量化上 Thor；按件触发、不常驻；与动作模型同机的显存与延迟实测；不达标则大脑放站点服务器 | 单件识别 ≤3 s；动作模型 ≥10 Hz 不受影响 |
| **S8 现场试运行** | 10–12 | 有人值守；人工筐与投诉回流成每周难例集；规则与提示库先改（当天可回滚），每 2 周 LoRA 刷新一次 | 交付一 a：错分率 ≤5%、每百件干预 ≤20 次 |
| S9 稳定化 | 13–20 | 新站点测试集验收；难例持续回流 | 交付一 b：错分率 ≤3%、高代价错分 ≤0.5%、弃权率 ≤10% |

训练细节：

- 损失按字段加权：`color_group` 与 `fabric_class` 权重高；高代价混淆对（深→白、精细→普通）额外加权。
- 多视角作为多图输入，训练时随机丢视角，保证少一路相机时退化而不是崩溃。
- 输出用受限解码保证 JSON 合法；置信度取字段首 token 的归一化概率，再过温度缩放，不用模型"口头报"的置信度。
- 每个发布版本记录 `brain_model_version`、`prompt_library_version`、`sort_policy_version`，写进每条识别日志与 episode 的 lineage。

## 5. 评测与验收

### 5.1 指标

| 指标 | 定义 | 第 4 周 | 第 12 周（交付一 a） | 第 20 周（交付一 b） |
|---|---|---|---|---|
| 分筐判别准确率 | 未弃权样本中，分筐与金标准一致 | ≥90% | ≥95% | ≥97% |
| 错分率 | 全部样本中，进了错误的非人工筐 | — | ≤5% | ≤3% |
| 高代价错分率 | 深 / 艳进白浅筐，或精细 / 不可烘未被拦住 | — | ≤1% | ≤0.5% |
| 弃权率 | 进人工筐的比例 | — | ≤15% | ≤10% |
| 单件抓取成功率 | 一次抓起且只有一件 | ≥85% | ≥90% | ≥93% |
| 单件识别耗时 | 触发到输出 | — | ≤3 s | ≤2 s |
| 订单混淆 | 不同订单衣物混筐 | 0 | 0 | 0（零容忍） |

**人工基线**：第 1–4 周请洗衣房师傅按现行做法在同一测试集上分筐，测出人工错分率；验收口径为"不劣于人工基线，且高代价错分达到上表"，上表的百分比在基线出来后校正。

错分率与弃权率要一起看：只压错分率会把一切都扔进人工筐。验收曲线是"错分率 – 弃权率"的折线，不是单点。

### 5.2 评测纪律

评测集衣物不进训练；评测由不参与模型开发的人执行；每个版本跑同一套测试集并留档；新站点测试集只在验收时用（eval-protocol §3 的盲测与序贯检验口径）。

## 6. 日志与数据回流格式

每次识别写一条事件进同一条 MCAP（data-format-contract §1.2 的 `/event/task` 族）：

```json
{"event":"garment_decision","order_id":"…","garment_seq":17,
 "frames":{"head":[t1,t2,t3],"wrist_l":[t4]},
 "attributes":{…§1.2…},"confidence":{…},"retries":1,
 "bin":"dark","abstained":false,"human_override":null,
 "brain_model_version":"…","prompt_library_version":"…","sort_policy_version":"v1"}
```

人工改判（`human_override`）与客户投诉单号事后回填。这样现场每处理一件衣服就自动产出一条带真值修正的训练样本，不需要另建标注任务。

## 8. 风险

| 风险 | 说明 | 对策 |
|---|---|---|
| 面料靠视觉分不清 | 羊毛 / 腈纶、真丝 / 涤纶仿丝外观近似 | 面料以洗标为准；无洗标且疑似针织 / 丝质一律人工筐；不把"视觉判面料"列为验收指标 |
| 洗标翻不到 | 位置不固定，机器人翻找代价高 | 只做"顺手看到就读"；不为找洗标设计专门动作（交付二再评估） |
| 湿、脏导致颜色偏移 | 湿衣偏深、污渍改变局部颜色 | 分类发生在洗前（干、脏）；训练集含脏污样本；颜色分组用展示位固定光照 |
| 长尾衣物 | 制服、民族服饰、儿童衣物 | 显式"其他 / 未知"类 + 弃权；回流难例每两周刷新 |
| 公开数据集许可 | 常见服装数据集多为研究用途 | 第 1 周核查；默认不依赖 |
| Thor 算力与动作模型争用 | 两个模型同机 | 按件触发、量化 4B；不达标放站点服务器（汇报稿 §8.1 前提 5） |
| 口袋有物看不见 | 人靠手摸，视觉只能看到明显鼓包 | v1 不做；服务条款约定客户自行清空；只对明显鼓包报注意项 |
| 衣堆过高一抓一串 | 倒袋后堆叠缠绕 | 宽台面 + 限高挡板先摊薄；"抖落 + 二次抓取"子技能 |
| 校准随 LoRA 刷新漂移 | 每两周刷新一次权重 | 重新校准列为发布门；校准集每月用回流难例更新 |
| 错分赔付 | 染色、缩水 | 高代价错分单列指标；低置信度一律人工筐；规则可按客户收紧 |

## 9. 不同类型衣物的泛化（2026-09-20 增补）

原则：**能设计成与类型无关的环节，就不让它依赖类型。** 交付一涉及两层，折叠与晾挂层见 [laundry-fold-hang-plan.md](laundry-fold-hang-plan.md)。

### 9.1 识别层：按属性决策，不按品类决策

- 分筐规则（§1.3）里没有品类，只有颜色分组、面料类、洗标项、注意项。没见过的款式只要颜色与面料判得出，分筐照样成立；`garment_type` 只服务交付二的折法选择，判错不会导致染色或缩水。
- 长尾靠三样兜底：显式"其他 / 未知"类；校准后的弃权（§4 S5）；人工筐每周回流成难例集（§3.1）。
- 第 1 周零样本基线（S0）要按品类分层报告，不只报总体准确率，用来发现 VLM 先验薄弱的品类。

### 9.2 抓取与装卸层：技能定义在"一团布"上

分拣、装洗衣机、转烘干机面对的都是布团，不需要知道品类。泛化的轴是物理属性，采集配额按下表分配，**不按品类分配**：

| 变量 | 档位 | 采集与训练要求 |
|---|---|---|
| 尺寸 / 重量 | 小件（袜、内衣）· 中件（T 恤、裤）· 大件（床单、浴巾、外套） | 三档各占遥操作数据 ≥20%；大件单列"分段提起"子技能 |
| 干 / 湿 | 干、半干、湿 | 夹持力阈值干湿两档标定；湿衣数据从第 2 周开始采，不排在最后 |
| 表面摩擦 | 滑（丝、涤纶）· 中（棉）· 涩（毛巾、牛仔） | 2–3 种指尖对照（U-04）；夹持力判"是否抓住"，件数判断见 §2 L1 |
| 缠绕 | 袖、裤腿、内衣带、床单裹小件 | "抖落 + 二次抓取"作为单独子技能；床单裹小件单列为注意项 |

实物清单：交付一准备 **约 60 件代表性衣物**，覆盖上表 3 × 3 × 3 的组合，每件打编号；任何单件衣物的演示数不超过该子技能总数的 5%，防止过拟合到具体某一件。

### 9.3 泛化的测法（进验收）

| 测试集 | 内容 | 用途 |
|---|---|---|
| T-in | 见过的品类、没见过的那一件（≥1,000 件，§3.3） | 常规验收 |
| T-type | **留一类不训**：每轮轮流留出一个品类（如留出牛仔、留出针织），只在测试时出现 | 识别层与抓取层的跨类型泛化 |
| T-site | 没见过的站点（300 件，§3.3） | 交付一 b 验收 |

报告口径：同时给出 T-in 与 T-type 的指标及二者之差（泛化差距）。判据：T-type 的分筐判别准确率比 T-in 低超过 5 个点即告警；单件抓取成功率在留出的尺寸 / 摩擦组合上不低于 80%。差距超限时优先补"物理属性组合"的数据，而不是补更多同类衣物。

### 9.4 品类白名单

交付范围按白名单写进验收口径：白名单内的品类计入错分率与干预率；白名单外一律进人工筐，不计入错分。白名单的扩展顺序由试点洗衣房的订单件数统计决定（**第 1 个月从现场取得，当前没有数据 ⚠️**）。每新增一类的流程：补属性样本 → 留一类测试 → 过泛化差距门 → 进白名单。

## 10. 第 1 周清单

1. 搭采集台，定拍摄规范与属性本体 v1、分筐规则 v1。
2. 采 300 件金标准集（含人读洗标），跑 S0 零样本基线，出逐属性准确率表。
3. 核查候选 VLM、SAM2 与公开数据集的许可，登记进 governance U-11 表；确定试点所在地的洗标标准。
4. 定教师模型与预标注流程；标注工具接好复核队列。
5. 与动作模型组对齐"展示位"姿态与触发接口、`garment_decision` 事件格式。
6. 采购二手衣物（按公斤）；启动内部洗衣服务；安排人工基线测试；向试点方确认现行分筐做法（[plans-review-hard-points.md](plans-review-hard-points.md) S-1、S-3、S-4）。
7. 备齐约 60 件代表性衣物并编号（§9.2）；向试点洗衣房要近 3 个月的订单件数统计，定品类白名单 v1（§9.4）。
