# 开源策略：边界 · license · 数据发布 · 社区

> 2026-09-08。仓库定位是"开源人形机器人数据管线与采集工具"，但采集到的数据、Creator 平台与商用部署有不同的开放边界。本文定边界，避免"开源"一词在文档里指代不同的东西。

## 1. 开放分层

| 层 | 开放度 | 内容 |
|---|---|---|
| 工具与规范（本仓库） | **开源** | recorder/ingest/curation/export/viz 代码、schema、data-format-contract、全部设计文档、UMI 改型图纸（若有） |
| 数据集 | **分级发布** | 见 §3：脱敏 + 单独授权的子集可发布（LeRobot v3 格式上 HF Hub）；其余内部 |
| Creator 平台（App/后台） | 内部（可能后续开源客户端） | 含反欺诈规则与计酬逻辑，公开会削弱反欺诈 |
| 模型权重 | 逐个决定 | Stage A/B 的研究 checkpoint 可发布；部署策略内部 |
| 自研头戴设备 | 硬件规格开源（P1 后）、固件部分开源 | 参照 Aria 研究套件做法；安全启动/证书部分不开 |

## 2. 代码 license 与依赖纪律

- 本仓库：**Apache-2.0**（与 LeRobot、MCAP、rerun 生态一致，允许商用集成）。
- 依赖：默认路径只允许 Apache/MIT/BSD/MPL；GPL 组件（ORB-SLAM3）只能作为**可选、服务端、独立进程**集成，不得链接进本仓库分发件（governance U-10）；非商用权重只进 `research/` 分支（cleaning-algo-selection 纪律 2）。
- 贡献者协议：DCO（signed-off-by）即可，不要求 CLA。
- 第三方模型权重不进仓库，用下载脚本 + 哈希校验；license 清单随 governance U-11 表维护。

## 3. 数据集发布前检查单

1. 只从 training 区取（已脱敏）；`consent_ref` 对应的协议版本包含"允许对外发布"勾选。
2. 区域：仅来自允许出境/发布区域（compliance §1）；中国大陆采集数据默认不对外发布。
3. 再脱敏复检：人脸、车牌、屏幕内容、文件/信件文本；语音不发布。
4. 数据集卡片：来源轨、设备、采集时间段、多样性计数、已知偏差（地域/人群）、license（CC-BY-NC-4.0 起步，商用另议）、引用方式。
5. 撤回机制：发布版本有 manifest，撤回请求触发新版本并在卡片记录。
6. 法务签字。

## 4. 社区与对标

- 对标对象：LeRobot 社区数据集、DROID、Open X-Embodiment、UMI 社区；目标是让本仓库导出的数据集"不改代码进 openpi/lerobot"（Stage A 放行判据本身就是互操作性测试）。
- 上游贡献优先于分叉：LeRobot v3 缺的字段（`*_mask`、`fdp.*` 列）以扩展列方式携带，不改其格式；需要格式变更时先提 issue/PR。
- 发布节奏：每个里程碑一个 tag（v0.1 = M1）、CHANGELOG、设计文档快照。

## 5. 商业边界（避免自我冲突）

- 开源工具不限制商用；平台服务、Creator 网络、精策划数据集是商业资产。
- 若未来出现"开源工具 vs 商业数据"的利益冲突（例如策展阈值是否公开），原则：**方法公开、阈值与配方版本化但可不公开**——文档里已把阈值全部放在 `configs/`，正是为此。
