## 1. Egocentric 数据处理管线：从原始视频到 LeRobot 数据集（对我们最有价值）

四阶段全算子清单（含算力标注），与本仓库伪标签工厂逐环节对照：

| 阶段 | 通义方案（算子 + CPU/GPU） | 对应我们的设计 |
|---|---|---|
| **① 内参估计与畸变矫正** | 长视频切分 20s+2s 重叠、ffmpeg 抽关键帧（CPU）→ Farneback 背景光流判定相机动/静（CPU）→ 动：**DroidCalib** 多视图运动自标定焦距（GPU）/ 静：**GeoCalib** 单图估径向畸变+焦距（CPU）→ 去畸变到标准针孔模型（CPU）→ **MoGe-2** 稠密深度+针孔焦距先验（GPU） | **补齐了我们的盲区**：众包/手机视频没有出厂标定文件，标定必须从视频本身估计——cleaning-algo-selection §1.7 原只覆盖自有设备（ChArUco/Kalibr），需增补此路线 |
| **② 3D 重建与位姿追踪** | 并行两支：A. **HaWoR** 双手 3D 重建→相机系手部 Pose（腕 6D + MANO 45）；B. MoGe-2 深度→**MegaSAM** SLAM→世界系相机位姿（静态相机跳过=identity）→ 汇合：相机系→世界系轨迹（CPU）→ SE3 对齐、**Savgol 平滑**、离群清洗、片段重组（CPU） | 与我们伪标签工厂 §4.2 同构；HaWoR（我们手部方案候选之一）与 MegaSAM 是具体选型答案；"静态相机跳过 SLAM" 是省算力的好细节 |
| **③ 原子动作分割** | 世界系**手腕移动速度→速度极小值点（Local Minima）→ 双手各自切分**原子动作（全 CPU）；输出 104D 状态 / 102D 动作（双手 MANO） | **验证了我们"速度极小值分割"路线**（curation-pipeline §3.2 第 3 条）——且他们把它当主方法而非兜底，VLM 完全不参与切边界 |
| **④ 语言标注与导出** | 每段均匀采样帧→**手腕轨迹投影叠加到采样帧**→Qwen-VL 视觉语言标注→生成双手命令式指令（VLM）→聚合导出 **LeRobot v3.0** + meta 校验 | 与我们方案一致；"轨迹投影叠加再喂 VLM" 是提升标注质量的可抄技巧（VLM 看得见运动轨迹而非只看帧） |

S2 补充（S2-p39/p40/p48/p49，四阶段算子与 S1 一致）：

- 流程图第三阶段的平滑写作"Spline 平滑 & 异常值剔除"（S1 与 S2-p40 写 Savgol），以哪个为准不确定；第四阶段写明"每段均匀采样 8 帧"。
- **导出布局**（S2-p48）：LeRobot v3.0，`data/chunk-000/file-000.parquet`（多 episode 拼接）+ `videos/` + `meta/{info.json, stats.json, tasks.parquet, episodes/}`；每帧列为 `observation.state[104]`、`action[102]`、**`action_mask[102]`**、**`camera_fov[2]`**；`tasks.parquet` 存**左右手各一条**指令（例："Left Hand: Grasp the left side of the box. / Right Hand: Hold the right side of the box."）。
- 客户输入只需"第一视角 MP4 1080p、双手操作、无需人工标注"；S2-p49 的区分值得记住：21 关键点是感知输出的**位置量**，腕 6D + MANO 45 DoF 才是训练与控制的**驱动量**。

## 2. 训练数据处理"双管线"设计

- **数据预处理管线（human→robot 合成）六步**：Input → Retarget & Smooth → Arm Segmentation → **Hand Removal**（视频里把人手擦除）→ Base Search + IK → **Depth Composite**（把机器人臂合成进原视频）。产出规模（slide 口径，较论文更新）：**1,933h 人类视频 → 15 本体 24,808h 演示；"零专有采集成本实现 38K 小时跨构型数据扩展"**。
- **数据清洗管线**：
  - 针对 Action（State-Action 数值与运动学校验，五阶段）：噪声移除、极值检测、修复时序错位、坐标系对齐、运动学一致校验；
  - 针对 Video（视觉-语言层三阶段过滤）：**指令-动作一致性检查、视频-状态一致性检查**、视频质量检查。
- 对我们的增量：前者与 L1/L2 吻合；后者的两个"跨模态一致性检查"（指令↔动作、视频↔状态）是我们 curation-pipeline 缺失的门类，值得补。

## 3. QwenRobot-Manip：三维对齐与统一架构

Qwen3.5-4B VLM 主干 + flow-matching DiT 动作头，端到端动作轨迹。三个"对齐"设计：

1. **表征对齐**：所有机器人状态/动作映射到统一 **80 维向量**（覆盖单臂/双臂/灵巧手/移动底座配置），输入输出加**二值掩码**保证梯度只流过有效维度——不同构型无冲突共享参数。（动作空间统一的第四方案，介于 π0 零填充与 RDT 128 槽位之间，掩码机制同 RDT）
2. **操作状态对齐**：末端动作以**增量形式表达在相机坐标系**下——视觉上相似的动作在不同构型间数值相近；相机外参通过注意力层 **CaPE** 注入、内参直接编码进视觉 token（感知视场角）。
3. **跨本体/上下文对齐**：结构化**具身感知提示**（机器人平台、执行速度、帧率）+ 历史观测-动作块预测当前动作。

S2 补充（S2-p12–p15）：

- **80 维的单臂槽位拆法**：Joint Pos 7D + EEF Pose 9D（3D 位置 + 6D 旋转）+ Gripper 1D + Dexterous Hand 12D，左右臂各一组再加其他部件。架构图上还有：VLM 输入为多相机多时刻帧 + 结构化具身提示（embodiment / instruction / speed）+ **具身思维链**（scene / progress / next）+ 经 Context MLP 的历史状态与动作；VLM 共训输出与 VLA 分批、互斥；DiT 用 AdaZeroRMSNorm 注入条件（去噪步、末端执行器类型、有无相机参数）。
- **缩放曲线**（S2-p12）：预训练数据从 1% 增加到 100% 时，下游成功率从约 30% 升到约 55%；去掉 UnifiedSpace 或 UnifiedEEF 后曲线明显变低。这是"统一表征才让多源数据产生协同"的自证据 ⚠️。
- **OOD 结果（自报 ⚠️）**：LIBERO-Plus（7 类扰动）91.4%；跨本体迁移 ARX-X5 42.9% / UR5-WSG 22.8% / Franka 5.9%（均高于前 SOTA）。真机 4 个 OOD 任务各 10 次：Ours 87.5%，π0.5 37.5%，StarVLA 0%。
- 真机 demo 的系统形态：Qwen3.5-Omni 做上层规划器，用语音提出任务并实时判断执行结果，Manip 负责执行。和 Nav 一样是"大模型规划 + 专用模型当工具"。

## 4. Qwen-VLA 与 GTA-VLA

- **Qwen-VLA**：操作 VLA + 导航 VLN + 视觉理解统一进共享动作/轨迹空间；**embodiment-aware prompt conditioning** 模板（可直接抄）：`The robot is {robot_tag} with {single arm / dual arms}[, waist][, and mobile base]. The control frequency is {FPS} Hz. Please predict the next {chunk_size} control actions to execute the following task: {ori_instruction}.`；四阶段渐进式训练；DOMINO 基准 OOD 成功率 26.6% 超主流专家模型。
- **GTA-VLA（ECCV 2026）**："Guide, Think, Act"——动作前先出**视觉提示**（框/点）做 grounding，解决直接 sense-to-act 的错定位问题；含歧义目标的人机交互澄清。

## 5. QwenRobot-Nav

- Qwen3-VL 基座的规模化导航模型：**2B–8B 参数一致扩展**；5 大导航域（VLN/ObjNav/Tracking/Driving/EQA）适配；**15.6M 训练样本**跨域训练；轻量 MLP 头输出路径点 (x,y,θ)×8。
- 参数化接口：任务模式 + 可控观测参数（**视觉 token 预算、时间衰减、相机权重、帧采样模式**）——训练时随机化这些参数，推理可任意设置。
- Agent 化设计：上层规划器（Qwen3.7-Plus）做子目标分解/工具调度，Nav 模型作为**智能体可调用的工具**；双级记忆（短期压缩轨迹 + 长期 notebook：已搜索区域/候选物位置/已排除假设）。
- S2 补充（S2-p8/p11，自报 ⚠️）：13 项细分 benchmark、8 项 SOTA。4B 在短程感知任务上更强（HM3D、EVT-Bench、NAVSIM 均超过 8B），8B 在长程推理任务上更强（VLN-CE RxR/R2R、EQA）。HM3D 75.6% SR 只用 RGB；NAVSIM 91.4 PDMS。真机部署在宇树 Go2 上，Jetson Thor 端侧推理延迟 196ms，只用 Go2 自带摄像头，在未见过的环境中零样本运行。

## 6. QwenRobot-World：语言条件视频世界模型（S2-p18–p20）

- **架构**：Double-stream MMDiT，60 层，总参数 27B（MLLM 7B + MMDiT 20B + VAE 127M）。理解流用冻结的 Qwen2.5-VL 编码语义和动作条件，生成流用 Wan-VAE 编码视频 latent；两流在每层通过 Joint Attention 双向融合，3D RoPE 非对称编码（时间 16 维 + 空间 56×56 维）。
- **数据**：EWK 数据集，8.6M 条具身视频-文本对；用自然语言把 20+ 种机器人构型、500+ 种动作类别统一成同一个动作接口，覆盖操作、驾驶、导航、人机迁移四个领域。
- **跨本体迁移模式**：输入是"去掉人手的场景视频 + 机器人参考轨迹（MuJoCo 仿真）+ 生成目标"，可以把同一场景下的人类演示生成为 14 种机器人本体的执行视频，不需要针对机器人的专属提示。这和 §2 预处理管线的 Hand Removal + Depth Composite 是同一个思路的生成式版本。
- **定位**：数据合成引擎、策略评估环境、动作规划器三用。自报在 EWMBench 和 DreamGen Bench 排第 1，在 WorldModelBench 和 PBench 开源第一 ⚠️。
- S2-p59–p61 的 **Wan-robot** 是另一条线：以 Wan/HH/Qwen-World 等闭源基模为底座的专用数据合成模型，改了 Wan 的结构以适配机器人后训练（单目视频生成多目视频），以闭源权重联合训练方式交付（见 §7.6）。

## 7. 阿里云计算平台具身数据管线方案（S2-p21–p63）

整体定位：阿里云计算平台（DataWorks / MaxCompute / PAI / DLF）与 Qwen 联合，把"数据质检 → 数据打标 → 数据挖掘 → 数据合成"做成一个飞轮（S2-p28）。各环节成熟度由对方自己标注：**质检已交付（仅 Ego 采集）**，打标是"更具性价比的成熟方案"，挖掘是"长期应用的成熟方案"，合成是"联合训练方案"，多 agent 质检协同还在"联合共创孵化"阶段。

### 7.1 平台分层（S2-p24/p29）

- 三类原始数据（真机、UMI、EGO）都进 **DLF 全模态湖仓**。具身数据研发分质检、标注、检索、合成四块，跑在 Ray / Spark / MaxFrame 上；具身模型研发分训练（PAI-DLC）、仿真评估（Isaac Sim/Lab）、推理（PAI-EAS）。最底层是 DataWorks 一站式开发治理。
- 和我们的对应关系：DLF ≈ 我们的数据湖，DataWorks 多模态数据集（S2-p54：OSS/NAS/DLF LanceTable 注册为数据集、版本化、标量/向量检索）≈ 我们的数据集层 + lineage，DataWorks 全链路血缘（S2-p55：表/文件 → 处理任务 → 数据集 → 训练任务 → 模型 → 部署 → 推理服务）≈ 我们 configs/mixtures 哈希入 lineage 的那条链。概念上没有新东西，可以当成"有人把它做成了商品"的参照。

### 7.2 具身数据质量评估框架 v2.0（S2-p32）

四个质量维度 × 四种数据形态的矩阵，评估目标写作"可入库 → 可训练 → 可交付"。判定方式是规则校验 + 模型自动质检 + 人工抽检：

| 维度 | Ego 采集（**已交付**） | Ego 标注（扩展中） | UMI 采集（未来） | 真机（未来） |
|---|---|---|---|---|
| ① 完整性 | Meta 完整；传感器流完整（RGB/IMU/深度，无丢帧）；相机内外参与标定文件齐备；Episode 切片与语言指令完整 | 帧级索引一一对应；手部标注完整（2D/3D 关键点 + MANO）；语言标注完整（Caption、子技能分段）；深度、物体框、接触点完整 | 相机序列号/Session；鱼眼视频 + IMU 原始流；夹爪标定与建图视频；SLAM 轨迹连续无断裂 | 本体型号/控制频率；多视角相机流；本体状态（关节、末端、夹爪、底盘）；力/触觉与成功失败标签 |
| ② 有效性 | 跨设备/跨模态时间戳对齐；画质（过欠曝、运动模糊、压缩伪影）；手部可见性与遮挡率；任务操作有效性（动作连贯、结果达成）；静止帧与冗余片段占比 | 手部标注精度（MPJPE、重投影误差）；不可见点与置信度标记规范；Caption 语义质量（颗粒度、无幻觉）；标注与传感器逐帧对齐；多标注源交叉一致性（人工 vs 模型） | SLAM 位姿精度与尺度一致性；夹爪开合宽度标定误差；相机-夹爪外参一致性；快速运动模糊与曝光抖动；重定位漂移与轨迹平滑度；任务有效性（接触、抓取成功） | 跨设备时间戳；相机画质；任务有效性；静止帧与无效等待；双臂协同（时序、空间无冲突）；Loco-Manipulation 轨迹有效性 |
| ③ 标准化与可训练性（"建议新增"维度） | 统一坐标系与单位；相机系 → 世界系变换规范；抽帧与编码规范（FPS、GOP、分片）；导出 LeRobot 标准结构 | 统一 MANO 拓扑与关节定义；Root-relative/相机系约定一致；State/Action 维度对齐；Schema 与标注版本可追溯 | 位姿对齐到 TCP/本体坐标系；夹爪宽度跨本体归一化；统一时间基准与重采样频率；导出 LeRobot | 状态/动作空间统一定义；遥操作控制时延补偿与重采样；跨本体动作归一化；LeRobot v3.0 分片与索引规范 |
| ④ 真实性与合规 | 数据真实（非合成、非二次转录）；采集授权与被采集人知情同意；人脸/车牌隐私脱敏；涉密场景与地理信息合规 | 标注来源标识（人工/模型自动）；自动标注所用模型许可合规；标注环节数据不出域、最小留存；标注返修与质检记录留痕 | 采集设备与过程可追溯；场地与被操作对象授权；环境隐私脱敏；第三方数据集 License 可商用 | 数据真实（非仿真冒充、非回放伪造）；客户现场/产线数据授权；工艺机密与厂区信息脱敏；数据血缘与交付版本可审计 |

对照我们：①② 与 curation-pipeline §1.1–§1.4 基本重合；**③"可训练性"作为独立质检维度**是我们没有单独列出的（我们把它分散在 data-format-contract 和 export 层）；④ 与 compliance-and-security + §1.6 反欺诈对应，其中"**自动标注所用模型许可合规**"和我们的 license 列规则是同一件事。

### 7.3 Ego 采集质检三阶段（S2-p33/p34，已交付）

- **输入**：ODPS 每日一张输入表，每行是一个四摄采集样本（sample_id / device_id / task_id / 规则 URI）；样本文件在 OSS（camera_0–3.mp4、逐帧时间戳 csv、audio.wav、imu.csv、metadata.json）；规则冻结为 `collection_rule.json`（任务标准动作序列）+ `quality_rule.json`（阈值/状态机/校验）。
- **S1 物性质检**（确定性算法，像素级，不用大模型）：规则快照加载 → 文件完整性 → 视频 probe → 时间戳对齐与丢帧 → blackdetect/freezedetect → 跨摄像头同步。Laplacian + ffmpeg，跑在 MaxFrame UDF 上。**明显损坏的样本在这一步直接拦截，不送入 AI 阶段。**
- **S2 语义理解**（VLM，qwen3.7-plus，经 MaxFrame UDF + DashScope 调度），**先粗后细两阶段漏斗**：
  - 粗筛：整段视频按 20s 窗口、5s 重叠、约 2s 取 1 帧，拼成 **5×2 联系图（Contact Sheet）** → 任务匹配 → 场景匹配 → VLM 粗推理 → 提取候选段（约占全片 30%）。
  - 细检：候选段前后扩 3s，合并候选后自适应采样 **20 点**（间隔 = max(0.5s, 时长/20)）→ VLM 细推理 → schema 校验 + 重试 → 边界精修 → 序列评估（每样本 2–3 个序列）→ 交互指标聚合。
- **S3 报告发布**：S1 left-join S2 → 指标汇总 → 像素与语义合并 → 候选段去重叠 → 序列状态判定 → 七重严格校验 → 写 OSS。产出每样本 `quality_report.json`、每日 `summary.json`，以及 s1/s2/s3 三张 ODPS 索引表。
- **19 项指标**（S2-p34；验证口径为 44 个样本、176 路视频、2.2h、8 并发；耗时 S1 275s / S2 1403s / S3 110s）：

### 7.4 AI 数据打标（S2-p37–p46）

**四阶段打标管线**（S2-p38）：

1. **全局规划**（LLM ×1）：三视角 + 传感器一次推理，产出任务概要、物体列表和粗分段。
2. **局部精调**（LLM ×N，8 路并发）：按粗段切 clip（约 1.5 倍窗口，约 10fps），LLM 精修边界（拆分/合并/修正），用 ReAct 循环在段内迭代（最多 2 轮），**不跨阶段回环**。
3. **确定性后处理**（纯代码，15 条规则）：碎片吸收、动作合并、边界吸附、连续性修复。
4. **描述重写**（LLM ×1，**不动边界**）：按 GT 风格把 action/description 改写成标准句式。

输入覆盖智能眼镜、头显、手机录像、UMI/动捕、机器人数据；输出 Action Clip、3D Pose、Observation、Quality Score，可以直接喂 LeRobot / OpenVLA / GR00T / Cosmos。自报"AI 自动完成 80%–90% 的标注工作，只保留复杂 bad case 给人工确认" ⚠️。

**他们总结的经验（S2-p41–p44），对我们最有价值的部分**：

- **打标要同时产出两样东西**：时间边界（一个原子操作从哪到哪）和语义描述（这段完成了什么状态变化）。子任务是 VLA 训练的中间监督信号，描述空泛就等于没有监督。
- **三种采集形态的失效点完全不同**：UMI 的问题是设备入画、抖动、边界最难定；Ego 的问题是没有空间锚点、动作最短最密；遥操作的问题是空闲多、任务模板化、错误会被批量复制。
- **规范本身是欠定义的**："接近算不算一段""微调算不算""空闲归谁""双手同时动怎么表达"在规范里没有可判定的答案，于是每个标注员自己发明一套规则。
- **三个瓶颈及数据**（自报 ⚠️）：
  - 卡在边界而不是描述：以欠分割为主，113 段中 63% 超过 10 秒、21% 超过 20 秒；模型之间缺乏共识，IoU≥0.5 的有 79%，但 IoU≥0.75 只剩 31%；短动作标不住，113 段里不到 2 秒的只有 1 段；切多切少取决于模型脾气而不是规范，同样 5 条视频，两个模型分别切出 48 段和 65 段。
  - 错误集中在少数难段：**42% 的人工标注段需要复核或大概率有错**（24 段中只有 14 段正确）；错的**不是动词而是指代**——容器、目标位置、结果状态；错误会系统性复制，一个容器指代错误在同一 episode 内连错 5 段；另一类是把 episode 级任务名当成段级描述（前 3 段全写同一句）。
  - 问题不全在标注员身上：按段计费诱导刷段，按时长计费诱导少切；没有待裁决通道，规范没覆盖时系统强迫给答案；采集端信息（失败、重拍、换道具）不传到标注端，标注员只拿到一个 mp4；评估口径也在反向激励——一对多匹配被丢弃，结果切得越细分越低。
- **他们的解法**："把规范变成机器可判定，再把人从'从零标'换到'只改错'"。阶段 A 先定边界（视觉输入构造 → 粗分割：整段输入 + 规范化 prompt，只切完成事件 + 不切清单 + 粒度先验 → 边界局部精修：在粗边界附近开窗重切，不外扩），阶段 B 再写描述（在固定边界上生成描述 → 多路交叉质检：描述投票 → 支持数/内部一致性/难度 → 风险分级 → 规范化 + 自动校验：形式违规不进人工队列，风险片段切片送定向审核台）。**先定边界再写描述，因为两个任务的失败原因不同，必须解耦。**
- **三条差异化主张**（S2-p44，自报 ⚠️）：
  - 同一套方法在不同采集形态上表现可以差 2.6 倍，通用管线必然在某一类数据上失效；要用客户的少量真实数据定制切分粒度、校验规则、描述模板和审核重点，并配一把评测尺子量化每轮调整的收益。
  - 标注粒度和时间精度不匹配下游用途时，训练效果下降 60%。训动作专家要帧对齐的连续轨迹，训高层规划器要语义边界与指令，做预训练则覆盖面优先于边界精度，三者的验收口径甚至互相矛盾。**同样的投入，在帧上叠加手部轨迹的收益是打磨切分规则的 3 倍。**
  - 标注资产不贬值：描述按**槽位结构化存储**，保留子边界与边界判据，版本全程留痕；skill 合并拆分、粒度调整、模板变更多数靠一次离线重映射，不用重标。并且要留下"现在几乎不用加工、以后很贵"的字段：**左/右/双手、成功失败、是否接触、关键帧**。
- **演进路线**（S2-p45）：今天人从"从零标"变成"只改错"（已落地）；下一步变成"只看高风险"（风险分级定向审核，规范空白由待裁决队列收口并回写规范）；目标是人只做"需求方"，数字员工 Agent 读懂规范、主动发现歧义并提问、自己跑评测迭代（明确写了"不作为当期交付承诺"）。

**评测口径单视频实证**（S2-p46，桌面整理任务，第一视角，自报 ⚠️）：

| 口径 | 他们的 SW-2 | 豆包 Seed 2.1 Pro | 差距 |
|---|---|---|---|
| ① 宽松：切点级 boundary F1（边界落在 0.3–0.5s 容忍度内即命中） | 57.6（P 50.0 / R 67.9） | 21.6（P 44.4 / R 14.3） | 2.7× |
| ② 严格：整段 IoU≥0.75 才算配对，1:1，禁止 1:N | 38.2（P 33.3 / R 44.8） | 5.1（P 10.0 / R 3.4） | 7.5× |

同一条视频，GT 人工标注 29 段，SW-2 切出 39 段，豆包切出 10 段（平均每段 10.7s，是 GT 的 2.9 倍）。结论是**口径必须先对齐**：粒度不够的切分在越严的尺子下越藏不住。这对我们 §3.2 分割器的验收指标有直接意义（见 §8 第 9 条）。

### 7.5 数据挖掘：Embedding 召回 + Rerank 精排（S2-p56–p58）

- **Qwen3-VL-Embedding**：双塔 Bi-Encoder，图/文/视频/文档混合输入，**32K token 输入**，64–2048 维可配置（可裁剪），30+ 语言；三阶段训练（大规模弱监督对比预训练 → 多任务对比学习 → 从 Reranker 蒸馏）。宣称相对 CLIP/SigLIP 的优势：原生视频输入（能用文本检索视频片段）、不受 77 token 上下文限制；相对"VLM 先写 caption 再做文本向量"的方案，不会在文本化时丢失空间关系、物体姿态和动作轨迹。
- **Qwen3-VL-Rerank**：单塔交叉编码器，对 Top-K 候选逐一深度交互后重排。具身例子："机械臂从左向右抓取红色方块"——CLIP 类模型给出的三个候选相似度接近，无法排序；Rerank 能区分方向、左右手、顺逆时针这类细微差异。
- **两阶段检索**：离线预计算全量向量 → 在线一次向量相似度召回 Top-K → Rerank 精排。车企 corner case 挖掘案例：22 个长尾标签平均召回准确率 70%+，其中 11 类 ≥95% ⚠️。
- 对照我们：curation-pipeline §2.1 的 embedding 选型以 SigLIP 帧特征起步，主要服务去重；演示库（§0 的 3–12s 切片）要"按任务 embedding 检索"，而这种检索恰恰需要区分动作方向和左右手，CLIP/SigLIP 做不到。Qwen3-VL-Embedding + Rerank 是一个现成的候选，**license 待核查**，核查前不得进入默认路径（见 §8）。

### 7.6 数据合成与受保护联合训练（S2-p59–p61）

- PAI 的"数据/模型保护联合训练"：客户 A 提供闭源数据或模型，以只读方式授权给 PAI；客户 B 在平台上受限使用（无 VPC/公网、无法进入容器、只能通过特定接口打印日志并被审计），可以自定义训练代码、查看 TensorBoard；训练后的 ckpt 按需导出，避免夹带数据。闭源数据一定不能导出，闭源模型可以按需导出，或者限制在阿里云上部署。
- 这是 Wan-robot / Qwen-World 闭源权重的交付方式。对我们的含义：如果采用他们的合成模型，**权重和合成数据的归属、可导出性要先谈清楚**，这关系到我们"raw 永存、lineage 可追溯"的原则。
