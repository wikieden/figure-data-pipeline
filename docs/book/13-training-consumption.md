# 第 13 章 训练如何消费数据

这本书讲的是数据管线，不是模型。但数据管线的每一个设计——分层采样率、槽位向量、相机语义名、帧对导出、奖励列——都是为某种训练消费方式准备的。这一章从数据的角度看训练层：模型要什么，数据层要为此做什么。训练层本身的设计在 [training-pipeline.md](../training-pipeline.md)，不在本仓库实现（fdp-policy 独立仓库）。

## 13.1 原则：数据引擎优先，模型设计保守

每个模型决策抄已被 ≥2 家独立验证的共识，创新预算全部留给数据层。理由来自"规模换参数"的证据：Octo 93M 训 80 万演示 ≈ RT-2 55B；OpenVLA 7B 训 97 万 OXE episode > RT-2-X 55B（论文）——**中等模型 + 大而多样的数据集是可行的开源路线**。

## 13.2 Figure Helix 的三层，和我们对应到哪

| S0 全身控制 | 仿真训练，1 kHz | 1 kHz | 范围外，留给 Isaac Lab 生态 |

决策三（分层采样率）就是这张表在数据层的投影。

## 13.3 架构决策与它们对数据的要求

[training-pipeline.md](../training-pipeline.md) §1.2 的八条决策，每条都对应数据层的一项交付：

| 架构决策 | 共识来源 | 数据层要交付什么 |
|---|---|---|
| VLM 主干 + 流匹配 DiT 动作头 | π0 / GR00T / RDT2 / 某大模型厂商 | 无特殊要求 |
| 两段式动作课程：预训练离散 token，部署流匹配 | π0.5 / Wall-OSS / RDT2 | 动作数值归一化统计 |
| 统一槽位向量 + 掩码 | RDT 128 维、某大模型厂商 80 维 | 96 维槽位 + 掩码（第 12 章） |
| 相机系增量末端动作为主 | UMI / 某大模型厂商；≥4 家收敛 | 相机外参、内参随数据走；`frame` 声明 |
| 具身感知提示条件 | 某大模型厂商模板 | 平台、频率、chunk 长度可从元数据读出 |
| 物理提示：演示入上下文 | GEN-1.5 | 演示库 3–12 s 切片，"物理提示可用"质量位 |
| 分层频率消费 | 与 schema 一一对应 | 不全局重采样 |
| 不做 S0 | — | — |

**物理提示接口要从第一天预留**：观测序列允许拼接演示片段 token。GEN-1.5 证明这个能力随规模涌现（自报 ⚠️），上下文里留演示槽位不花钱，事后加要动架构。对数据层来说，这意味着演示库不是"以后再做"的东西。

## 13.4 观察名单与可选分支

- **世界-动作模型（WAM）目标**（next-frame 与 next-action 协同预测）：2026-09-14 从观察名单升为可选分支（U-37）——Dyna-2、NVIDIA DreamZero、AgiBot GE-Act 2.0、Cosmos Policy 四家独立验证。仍不做默认路径，因为四家都没公开与纯动作目标的可控消融。数据层唯一要求：**export 保留连续帧对**（契约 0.3）。
- 不抄的：仅一家的统一异步流（Harmonic Reasoning）；自回归离散动作做部署头；每具身独立 MLP 头。

## 13.5 规模阶梯：数据量决定模型档位

| 档位 | 骨干 | 触发条件 |
|---|---|---|
| S（0.45–0.5B） | SmolVLA 类 / Qwen-VL 最小杯 | 现在；混合等效 <1e3 小时时的唯一 0→1 档位 |
| M（2–4B） | Qwen-VL 3B/4B 级 | 混合等效 5e3–1e4 小时、具身数 ≥10 |
| L（7B+） | 届时最强开源 VLM | >1e4 小时 / 20+ 具身，且 M 档未饱和 |

档位切换只看两个量：混合等效小时数，和缩放曲线是否仍在下降。**不按日历切换。** 小数据喂大模型是浪费（GEN-0 骨化相变，自报 ⚠️）。

## 13.6 训练课程四阶段

```
Stage A 管线验证    微调 openpi(π0)/SmolVLA on 10–50h 精策划 robot 轨数据（LoRA，单卡）
                    通过判据：仿真基准显著优于零样本；证明数据层无毒
Stage B 0→1 预训练  数据 <1e3h 不启动；先离散 token 后流匹配；
                    四轨混合：human 打底 / sim 中层 / device+robot 顶层
                    止损门：不超 Stage A 微调对照 → 回退查数据
Stage C 后训练      任务 SFT（高质量分层过滤子集）+ 演示库物理提示评测
Stage D RL 闭环     奖励分类器（QC 成功/失败/介入标记直接当标注）→
                    HIL-SERL / 冻结基座 + 残差 SAC
持续    评测 CI     每个 checkpoint 跑 LIBERO/RoboTwin 子集 + 少样本适应基准
```

注意 Stage A 的定位：它不是为了得到好模型，而是**证明数据层无毒**。一条管线可能每个环节都"看起来对"，但只要相机名映射错了一处、归一化统计算错了一处，微调就会比零样本还差。Stage A 是对整条 M1 管线的端到端验收。

Stage D 的数据来源完全来自质检：QC 状态机里的 success / failure / intervention 标记直接就是奖励分类器的标注。这是"标记不删除"的又一个回报。

## 13.7 数据配方是一等公民

`configs/mixtures/*.yaml` 声明各轨、各任务簇、各质量层的采样权重与温度，配方文件哈希进训练 run 元数据。任何模型都可以回溯到确切的数据配方。

配方的结构（roadmap L6 与 GR00T 2 的启发）：

- 按 `track`、`source`、`embodiment` 设份额；
- 合成数据按 `source` 单独成组；
- play 数据单独成组；
- 目标域 ≤5%，广度优先（Stage B）；
- 元数据条件化：低质、失败、自主 rollout 数据带标签入训练。

**汇率问题**：人类视频一小时顶几小时遥操作？GR00T 2 只证明了人类视频的边际收益为正，没给出换算。任何按他家配比照搬预算的做法都没有依据，只能靠我们自己的换算率实验（U-40）。

## 13.8 自建工具：数据引擎的方向盘

[training-pipeline.md](../training-pipeline.md) §3.2 的五个自建工具（M3 交付）：

1. **mixture-runner**：读配方 → 构建混合流式数据集 → 提交训练 → 登记 lineage。消融 = 多配方并行。
2. **scaling-fitter**：对消融结果拟合 L(D) = (D_c/D)^α，加按场景/物体/操作者切分的多样性幂律检验，输出"下一小时数据该采什么"的预算建议。**这是数据引擎的方向盘。**
3. **fewshot-bench**：从演示库抽 1 条 / 5 分钟数据，做零梯度 in-context 与 10 步微调两种评测——比全量微调更灵敏的数据质量探针。
4. **reward-trainer**：从 QC 标记批量训练任务奖励分类器，Stage D 与 L3 语义审计共用。
5. **eval-CI**：checkpoint 触发的仿真回归 + 指标仪表盘 + 真机协议模板。

## 13.9 工具链版本的教训

lerobot 0.7.0 于 2026-11-05 发布。0.6 有两个**静默失效**：`--policy.use_peft=true` 实际跑全参微调；批量图像增强中 7 种变换在 uint8 帧上是空操作（[research-rd-tooling.md](../research-rd-tooling.md) §7）。所以 Stage A 的 LoRA 单卡与任何开增强的对照实验必须在 0.7 上跑；外部或历史报数若来自 0.6，标注版本后再比较。

这条教训对数据层同样适用：工具版本要进 lineage，否则"同一个配方两次结果不同"就无从排查。

## 13.10 本章小结

- 训练保守、数据创新；中等模型 + 大而多样的数据是可行路线。
- 每条架构决策对应一项数据层交付：槽位、相机系动作、演示库、帧对、奖励列。
- 模型档位由数据量和缩放曲线决定，不按日历。
- Stage A 是数据层无毒性的端到端验收；Stage D 的标注来自 QC 标记。
- 配方是版本化一等公民；汇率只能自己测。
- scaling-fitter 是数据引擎的方向盘。
