# 第 16 章 合规、安全与治理

具身数据比互联网数据更"私密"：它在别人的家里、办公室里、厨房里录下来，里面有人脸、有旁观者、有家居布局、有声音。"隐私是生存问题"（[index-replica-plan.md](../index-replica-plan.md) §0）。这一章讲本仓库怎么把合规做成管线的一部分，以及怎么用治理登记管住设计里的不确定性。本章不是法律意见，每个区域上线前需法务出具意见（R-01 / R-11）。

## 16.1 "raw 永存"的准确表述

决策四说 raw 永存，隐私脱敏除外。准确的表述是（[compliance-and-security.md](../compliance-and-security.md) §6）：**脱敏后的原始 episode 永久保留，除非法律或数据主体要求删除。**

| 数据 | 保留 | 例外 |
|---|---|---|
| raw（脱敏后存档） | 永久 | 撤回或删除请求、未成年人、违法内容、区域法规强制 |
| raw 脱敏前帧哈希 | 90 天 | 审计用 |
| 原始音频 | 30 天 | 口令转写文本永久 |
| Creator 身份与支付 | 关系终止后按财税法规（通常 5–7 年） | |
| 审核台记录 | 3 年 | |
| 中间产物 | 90 天（可重算） | |

## 16.2 区域矩阵

| 区域 | 主要法规 | 数据驻留 | 跨境训练 |
|---|---|---|---|
| 中国大陆 | 个保法、数据安全法、生成式 AI 管理办法 | raw 与个人信息境内存储 | **默认不出境**，训练在境内 |
| 欧盟 / 英国 | GDPR、AI Act | 欧盟区域 | SCC + 传输影响评估；家庭场景 DPIA 必做 |
| 美国 | CCPA/CPRA、州生物识别法 | 无强制 | 可；BIPA 州禁止人脸生物识别或单独同意 |
| 其他 | 逐国 | 逐国 | 未评估区域不开放 App |

实现：EpisodeMeta 的 `region` 字段决定 bucket 区域与合规开关集（人脸处理方式、保留期、删除 SLA）；跨区训练只用**已脱敏的 training 区**数据，raw 不跨区。

2026 下半年的监管叠层让这件事从"合规成本"变成了"交付条件"：欧盟 Data Act、CRA、PLD、机械法规（2027-01-20 起适用）的叠层，以及中国 YD/T 6771-2026 八维数据质量标准（2026-11-01 实施）都要求机器可读的来源、同意与生命周期记录（[data-strategy-roadmap.md](../data-strategy-roadmap.md) §1.7）。

## 16.3 同意与旁观者

**Creator 协议要点**：

- 授权范围覆盖训练、评测、衍生数据集（含具身转换等派生产物）；对外发布数据集需**单独勾选**；
- 撤回后 30 天内从 raw / curated / training 删除；**已训练完成的模型不回滚**，但记录在案，后续数据集版本剔除——必须在协议明示；
- 按通过策展的分钟数计酬，费率与信誉分级公示。

**旁观者与未成年人**：

- 端上：硬连线录制指示灯 + App 强提示；可选端上人脸模糊；
- 入湖强制：人脸检测 + 模糊（EgoBlur，Apache）；检出未成年人特征的 episode 进人工审核，确认后整段拒收并从 raw 删除——"raw 永存"的合法例外之一；
- 误模糊：脱敏前帧哈希留存 90 天供审计，误模糊率进 QC，误模糊的 episode 标 `flag:overblur`，不删除；
- 语音：环境音频默认不入训练集，仅口令段附近 ±2 s 保留转写文本。

**家居 3D 孪生**（Creator 场景扫描经 SimFoundry 重建的物体清单、布局、网格）视为敏感个人数据：入网时单独勾选同意；按 `region` 驻留、不对外发布；随 Creator 删除请求一并删除，**并传导到由其派生的 sim 轨 episode**（`parent_episode_id` 链）。

## 16.4 删除传导

删除是 lineage 设计的最终检验。流程（compliance §4）：

```
deletions 表登记 → raw → curated → training → 数据集 manifest 剔除
                → 派生 episode（转换、合成、增殖、孪生）沿 parent_episode_id 链删除
                → 受影响的 training_runs 登记（模型不回滚）
```

SLA 30 天，第 21 天未完成告警；每季度随机抽查删除请求是否真的删干净。查询快照引用的片段同样在传导范围内——这是"查询即配置、快照进 lineage"的另一个用处。

## 16.5 数据分级与访问

| 级别 | 内容 | 访问 |
|---|---|---|
| L3 受限 | raw 未脱敏视频、Creator 身份、支付信息 | 平台运维 + 合规专员；双人审批；只读 |
| L2 内部 | 脱敏后 curated、元数据、审核台 | 数据、策展、训练团队 |
| L1 可共享 | training 区脱敏数据集、统计指标 | 全员；对外按开源策略 |

raw 区只有 ingest 写、审计读；所有 L3 访问、删除处理、数据集发布记录写入不可篡改存储，保留 3 年。模型网关在调用外部 API 前做数据分级检查。

## 16.6 安全基线

- 设备：固件签名 + 安全启动；OTA 签名包与灰度；本地存储加密，密钥与账号绑定，丢失可远程吊销。
- 端点：设备证书 + 短期 token；无证书上传直接拒绝。
- **投毒防御**：新账户全量审计；跨账户 embedding 碰撞；红队植入测试；训练前 held-out 泄漏检查；单账户短期大量高相似上传自动冻结。
- 供应链：依赖锁定（`uv.lock`）、镜像签名、模型权重哈希校验。

## 16.7 license 纪律

模型和资产的 license 是一个容易被忽视、一旦出事就很难补救的风险。本仓库的纪律（[cleaning-algo-selection.md](../cleaning-algo-selection.md) §2）：

1. **每个模型的版本与权重哈希进 lineage**——模型升级 = 数据世代切换，必须可追溯；
2. **⚠️ 待核查项在 M2 策展实现开始前完成 license 终审；非商用许可的模型只允许出现在研究分支**（DOVER、FAST-VQA、pyiqa 等）；
3. 所有 AI 判定阈值与传统阈值一样服从消融裁决；
4. 商业 API 没有权重哈希，改记**模型名 + API 版本字符串 + 调用日期**，其服务条款对"输出用于训练数据"的许可属于终审范围。

几个具体例子：UMI 原配的 ORB-SLAM3 是 GPLv3，只允许服务端处理、不得进设备固件或分发件，商用发行前须切到 BSD 的 Basalt 或完成合规评估（U-10）；SimFoundry 本身 Apache-2.0，但默认安装链含非商用组件，进默认路径前要换件（U-20）。逐项核查状态在 [governance.md](../governance.md) 的 U-11 表。

## 16.8 治理登记：管住不确定性

一个设计里充满了"暂时这么定"。[governance.md](../governance.md) 用三张活表管住它们（截至成书日约 29 条风险、51 条未决决策、34 条自报数字）：

| 表 | 内容 | 每条必须有 |
|---|---|---|
| R 风险登记 | 合规、经济、技术、供应链风险 | 严重度、触发信号、对策、owner、复检时点 |
| U 未决决策 | 待裁决的设计选择（如 U-47 合成归属、U-48 挖掘模块、U-49 平台底座） | owner、选项、裁决依据、状态 |
| D 自报数字 | 设计依赖的他家自报数字 | 来源属性、依赖它的设计、**若不成立怎么办**、对冲或探针 |

D 表的"若不成立"一栏是关键。例如 D-01（Index 五阶段策展）：若阶段划分错了，状态机与漏斗要重排；对冲是各阶段的具体方法全部来自可验证的一手来源（Wall-OSS、Cosmos、厂商论文），五阶段的正确性实质上不依赖 Figure。

规则：**新增风险、新增依赖他家数字的设计决策、新增待裁决项，都必须先在这里登记，再写进设计文档。** 状态只有 `open / mitigating / closed / accepted` 四种；owner 按角色（DATA、CUR、TRAIN、HW、PLAT、LEGAL、PM），不按人名。

## 16.9 引用纪律

最后一条治理规则关于"怎么说话"（[CLAUDE.md](../../CLAUDE.md) 约定）：

- 涉及他家的事实性宣称，引用 `docs/research-*.md` 的已核查条目，不凭记忆写；
- research 文档引用公司一手页面时，必须指向 [sources/](../sources/MANIFEST.md) 下的归档文本（URL、页面日期、抓取日期、HTML sha256），未归档的先归档再引用；
- 引用他家数字必须标注来源属性（官方确认 / 第三方 / 公司自报 ⚠️）。

这本书本身也遵守这条纪律。

## 16.10 本章小结

- raw 永存 = 脱敏后永存，法律或数据主体要求时删除。
- `region` 驱动驻留与合规开关；raw 不跨区。
- 同意要细分（发布、家居孪生单独勾选）；撤回后模型不回滚但登记。
- 删除沿 lineage 传导到所有派生产物，季度抽查。
- license 纪律：权重哈希进 lineage，非商用只进研究分支。
- 治理三表管住不确定性；D 表必须写"若不成立"。
