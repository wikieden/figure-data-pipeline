## 0. 结论先说

1. **采集设备的选择，本质上是在替训练算法做选择。** 一台设备决定了数据的四个属性：动作真值有多硬、训练时看到的画面和机器人部署时看到的画面差多少、有没有力和接触信号、每可用小时多少钱。这四个属性分别决定了：数据能进模型的哪一部分（视觉/世界先验 vs 动作专家）、要不要"具身转换"算法、接触密集子技能的上限、以及能不能堆到预训练需要的规模。各家路线的分歧（§2）几乎都可以从这四个属性推出来。
2. **行业已收敛的三件事**（§2.3）：人类是主要数据源，机器人数据退为对齐层；质量与多样性比数量更值钱，四家分别给了量化证据；动作空间收敛到"相机系相对末端位姿 + 开合度"。**仍在分歧的两件事**：人类数据怎么变成动作真值（硬件记录 vs 视觉伪标签），以及模型分不分层。
3. **对客户最重要的判断：洗衣场景必须以"与机器人末端同构的穿戴采集器"作为动作真值主力，头戴第一视角视频作为广度预训练，机器人遥操作只做对齐层和干预段。** 理由有三：洗衣时人手大半被布遮住，视频伪动作的通过率可能远低于一般家务（R-25）；客户只服务自研本体，同构采集器的观测与动作可以零转换直接进动作专家（[capture-devices-design.md](capture-devices-design.md) §1.1）；自变量公开的配比实验显示少量真机做"物理锚"即可（10:1，公司自报 ⚠️ D-31）。
4. **长期通用能力靠三条护栏，而不是靠多采洗衣数据**（§8）：① 动作以具身无关的形式为主存储（相机系相对末端 + 开合度/手关节），关节空间只作次级视图，这样末端从二指夹爪换到 T/I/S 两节手时旧数据不报废；② 头戴视频覆盖家务全域，洗衣只占一部分，否则模型的先验会被锁死在洗衣房；③ 失败与恢复段、速度带、来源等元数据全部保留，用元数据条件化训练，不删。
5. **客户可能有一个别家没有的数据源：自家洗衣机 / 烘干机本身**（⚠️ 待内部确认）。门状态、筒内负载重量、程序进度、故障码如果能作为时间戳对齐的事件流进入数据，就同时解决了三件事：程序启动卡点（R-23）、"筒内取空"的检查（plans-review W-4）、以及强化学习需要的自动奖励信号。建议把"家电事件流"列为第五件采集设备（§5.1）。
6. **推荐训练路线：三层结构 + 四阶段课程，自有预训练按数据门触发而不是按日历启动**（§7）。0–5 个月按方案 A 精简版做外取基座（π0.5，Apache-2.0）后训练 + VLM 大脑；同构采集器数据从第一天就进后训练（与遥操作混训）；当同构真值 + 视频达到 1e3 小时、且叠衣泛化探针不过时，启动自有 S 档预训练；达到 5e3–1e4 小时再上 M 档（2–4B），并打开"联合预测未来帧"的配方开关做对照（U-37）。

## 1. 评估框架：设备 → 数据属性 → 训练算法

[device-landscape.md](device-landscape.md) §0 给出了五个因子（F1 观测同构度、F2 动作真值等级、F3 力/接触信号、F4 规模经济、F5 任务覆盖）。本文在此基础上加两个对客户关键的因子，并把每个因子对训练算法的影响写明。

| 因子 | 问的是什么 | 对训练算法的直接影响 |
|---|---|---|
| F1 观测同构度 | 训练画面和部署画面差多少 | 差距大 → 需要具身转换（抹人手、合成机械臂、遮罩），或只能把这部分数据放进低权重 / 只监督视觉的目标；差距为零 → 可直接与遥操作数据混训进动作专家 |
| F2 动作真值等级 | 无标签 < 视觉伪标签 < 末端级硬件真值 < 逐指级硬件真值 | 决定数据进预训练的哪一层：无标签只能训视觉表征或世界模型目标；伪标签可训动作但要带可靠性权重；硬件真值可直接进后训练 |
| F3 力 / 接触 | 有无夹持力、触觉、关节电流 | 有 → 可作为策略输入通道，也可作为抓取成败的自动标签和奖励信号；无 → 接触密集子技能（湿衣分离、筒内取衣、捏单层布）只能靠视觉，失败率与数据需求都更高 |
| F4 规模经济 | 每可用小时全成本 | 决定能不能堆到预训练规模（1e3 → 1e4 → 1e5 小时）；不能堆的数据只适合后训练 |
| F5 任务覆盖 | 这种形态能演示哪些任务 | 决定模型先验的广度，直接关系长期通用能力 |
| **F6 硬件换代存活度**（新增） | 末端或本体换代后，这批数据还能不能用 | 存的是关节角 → 换代即报废；存的是相机系末端位姿 + 开合度 + 原始传感器 → 可重新投影到新末端 |
| **F7 洗衣场景适配**（新增） | 湿布、遮挡、缠绕、筒内深处，设备还能不能稳定出数据 | 手被布遮 → 视觉手姿估计失效；鱼眼对着移动的布 → VIO 漂移（capture-devices-design §1.1 已规定鱼眼朝外上方）；湿衣重量 → 夹持力量程 |

没有一种设备七项全优：末端越同构、真值越硬（F1/F2/F3），任务覆盖和规模就越窄（F4/F5），这是多轨采集的根本依据（[device-landscape.md](device-landscape.md) §0）。**F6 是本文想强调的：长期通用能力的一半在数据存法上，而不在采集量上。**

### 2.2 四种"人类数据 → 动作真值"的做法与训练代价

| 做法 | 代表 | 每可用小时成本 | 训练侧要付出的代价 | 洗衣场景适配（F7） |
|---|---|---|---|---|
| **A. 纯视频 + 视觉伪动作** | Dyna、某大模型厂商、Figure Index | 最低（众包事实价约 $6/h，[data-strategy-roadmap.md](data-strategy-roadmap.md) §0） | 伪标签工厂（标定估计、手姿、SLAM、平滑、可靠性评分）；手指 / 力缺失；往往需要 WAM 目标或抹人合成来弥补 | **差**：布遮手，手姿估计通过率可能远低于一般场景（R-25，未实测）；二指夹爪也无法直接执行人手抓法 |
| **B. 穿戴孪生 + 具身转换** | Sunday 手套 | 低（$200–400 / 只） | 需要 Skill Transform 这样的转换模块；"手套优先、机器人围绕手套设计"（迭代约 100 版） | 中：真值可靠，但湿衣会弄湿手套与相机；转换模块对布料遮挡的鲁棒性未知 |
| **C. 同构手持 / 穿戴器** | Generalist、UMI、自变量无本体、TwinDEX | 中低（UMI $400 / 只；TwinDEX 外骨骼成对，佩戴负担更大） | 几乎为零：观测与动作同分布，可直接与遥操作混训；只需运动学可行性门与物理回放门 | **好**：腕相机与机器人同位，看到的就是机器人会看到的布；夹持力可同步记录 |
| **D. 机器人遥操作** | 所有家的对齐层 | 最高 | 零域差；但规模受机器人台数限制 | 好，但六台本体同时要做采集、评测、联调、试点（[dyna-replica-plan.md](dyna-replica-plan.md) §12.4） |

**我方判断**：A 的价值在广度（家务全域的视觉与动力学先验），C 的价值在精度（直接可执行的动作），D 的价值在物理锚定与干预纠错。三者不是替代关系，而是喂模型不同部分。B 对客户不划算：客户末端已定（或在定），让采集器去镜像机器人末端（C）比让机器人去镜像手套（B）工程量小一个数量级，且不需要转换模块（[capture-devices-design.md](capture-devices-design.md) §1.1）。

### 2.3 收敛与分歧

已收敛（四家以上独立证据，[research-four-routes.md](research-four-routes.md) §5.4、[data-strategy-roadmap.md](data-strategy-roadmap.md) §1.3）：

1. **人类是主要数据源，机器人数据是对齐层**：每任务机器人数据 Figure 8–60 h、Dyna ≤10 h、Generalist ~1 h、Sunday 单条示例（全部自报）。
2. **质量 > 数量**：Figure 少三分之一数据 +40%；Sunday 高质量子采样 +32 点；Generalist、Dyna 均有类似表述（自报）。
3. **动作空间**：≥4 家收敛到相机系相对末端动作；骨干全部来自开放 VLM，Qwen 系是 2026 事实标准；动作头收敛到 ~0.3B 的流匹配 DiT（[research-open-ecosystem-2026.md](research-open-ecosystem-2026.md) §3.3）。
4. **头部 + 手内双视角**：Figure 头相机 + 掌心相机、Sunday 相机帽 + 手套相机、Dyna 头部吊舱 + 腕相机（后者为图片推断 ⚠️）。

仍在分歧：

| 分歧 | 两边 | 对客户的取舍 |
|---|---|---|
| 动作真值来源 | 硬件记录（Generalist、Sunday、自变量）vs 视觉伪动作（Dyna、某大模型厂商） | 洗衣场景取硬件记录为主；视频伪动作只做广度预训练且带可靠性权重（§3.1） |
| 模型分层 | 三层时标（Figure、Dyna）vs 单流（Generalist、Sunday） | 取分层：客户有"识别 / 分筐 / 洗标 / SOP 编排"这类明确的语义层任务，且需要与家电接口交互，分层更好调试与验收（§7.1） |
| 训练目标 | 纯动作 vs 联合预测未来帧（WAM） | 作为配方开关保留，用自家数据做对照再定（U-37）；它恰好是消化"动作不可靠的洗衣视频"的最好办法（§3.2） |
| 骨干来源 | VLM 初始化 vs 从零 | 取 VLM 初始化：客户数据量在 2 年内到不了从零训练的规模，且语义层需要 VLM 的世界知识 |

## 3. 数据形态如何约束训练算法（逐项）

### 3.1 动作真值等级 → 数据进模型的哪一层

```
数据形态                       能监督的目标                          在配方里的位置
─────────────────────────────────────────────────────────────────────────────────
无标签视频（人或机器人）      视觉表征、未来帧预测（WAM）             预训练打底，权重低
视频伪动作（手姿 → 腕位姿）    上述 + 带可靠性权重的动作目标             预训练，按可靠性加权
同构采集器硬件真值            动作专家（直接）、进度 / 成败标签         预训练主力 + 后训练混训
机器人遥操作                  动作专家（物理锚）、干预纠错              后训练，目标具身 ≤5% 预训练
部署回流干预段                DAgger / RL、奖励模型                    后训练迭代，单位价值最高
```

关键约束：**伪动作不可靠的数据不能直接喂动作头**（[data-strategy-roadmap.md](data-strategy-roadmap.md) L4 负选择："不做人类视频直接微调动作头"）。JoyAI 指出朴素混合会导致负迁移；ZETA 显示目标具身数据只要 5% 就 +13.4pp（L4，论文）。所以洗衣视频要么只进视觉 / 未来帧目标，要么带可靠性权重进动作目标。

### 3.2 观测同构度 → 要不要具身转换算法

- 同构采集器（C）：腕相机画面与机器人同分布，**不需要抹人手**，只用同一个视觉编码器的特征距离监控分布差异（[capture-devices-design.md](capture-devices-design.md) §1.1 验收项）。
- 头戴视频（A）：人手臂入镜。三种处理，代价递增：① 只作视觉 / 未来帧目标，不处理；② 手部区域遮罩后再训；③ 某大模型厂商式擦除人手 + 合成机械臂（六步管线，[research-vendor-robotics.md](research-vendor-robotics.md) §2）。**我方判断**：客户先用 ①，因为 WAM 目标本身就能利用"人手如何让布变形"的视频动态，不需要动作真值；③ 的合成管线工程量大，留到 human 轨规模过 1e4 小时后再评估。
- 采集器的头部相机（视场与安装高度对齐本体头部 D457）：人手臂会入镜，只作低权重输入（capture-devices-design §1.1）。

### 3.3 力 / 接触 → 接触密集子技能的上限

洗衣房的难点几乎全是接触问题：衣堆单件分离、湿衣缠绕取出、台面捏起单层布、开关门（plans-review §1 卡点 2、4、7）。

- 同构采集器加夹持力（指根测力或驱动电流，200 Hz，与本体同量纲）：既作策略输入，也作抓取成败与"抓了几件"的自动标签（与开度 + 提起重量 + 视觉合判，plans-review S-2）。
- 触觉：RealDexUMI 在接触任务上触觉 88.75% vs 无触觉 70%（论文）。**建议**在 T/I/S 两节手的指面预留触觉阵列安装位，先做 ≤500 h 对照集（与 L1 的触觉探针一致），不进默认路径直到消融通过。
- 视频路线给不了这个维度，这是 R-25 之外选择同构采集器的第二个理由。

### 3.4 动作空间与采样率 → 跨具身与动作头设计

- 主动作空间：**相机系相对末端位姿（3D 位置 + 6D 旋转）+ 开合度 / 手关节**，定长槽位向量 + 有效掩码（[training-pipeline.md](training-pipeline.md) §1.2 第 3–4 条，U-23 已裁决）。关节空间槽位保留作次级视图。
- 采样率：状态 / 动作 100–200 Hz（本体上肢 ≥200 Hz），视觉 10–30 Hz；同构采集器 VIO 60 Hz 按原生频率入湖，不上采（CLAUDE.md 决策 3 的 device 轨豁免）。
- 动作块：流匹配头 H=50 起步（π0 口径）；Thor 上 π0 实测 19 Hz（VLA-Perf，[research-open-ecosystem-2026.md](research-open-ecosystem-2026.md) §0），满足 ≥10 Hz 的小脑要求。

### 3.5 失败、恢复与速度 → 后训练和 RL 能不能做

- **失败 / 恢复段**：π0.7 用元数据条件化吃失败数据，AgiBot World 2026 刻意保留失败轨迹与介入帧（L6/§1.4）。采集 SOP 要求每个任务模板附"扰动-恢复"子任务（TAMEn 模式，capture-devices-design §6）。
- **速度带**：GO-1-Pro 发现操作者速度多模态有害；Sunday 要求采集员放慢、机器人以 75% 人类速度运行（L1）。同构采集器带可调阻尼，把人手开合速度限在本体夹爪速度包络内；速度带作为元数据而非追求多样性。
- **成败自动标签**：夹持力、家电事件流（§5.1 HX-5）、筐体称重对账，三者给出不需要人工的成败与进度信号，直接喂奖励模型（Stage D）。

### 3.6 多样性与长期通用能力

- Sunday 的"泛化差距"随预训练规模从 82 点收敛到 0（自报 ⚠️ D-25）；GE-Act 2.0 给出技能覆盖度与零样本 OOD 成功率 r=0.80（论文，[research-open-ecosystem-2026.md](research-open-ecosystem-2026.md) §3.2）。**含义：通用能力来自技能和场景的覆盖面，不来自单一任务的小时数。** Figure 用"每 1,000 小时的任务 / 物体 / 环境数"作为多样性 KPI（官方 D-09）。
- 自变量的纯无本体实验显示，人背着设备移动带来的视角与高度变化打破了固定基座数据的空间过拟合（未见高度 0.45 m 上 60%，自报 ⚠️）。客户本体有升降腰，采集员需覆盖站姿 / 蹲姿两档高度。

## 4. 客户场景分析

### 4.1 两个场景，一条数据资产线

| | 无人洗衣房（B 端，近期） | 家务（C 端，长期） |
|---|---|---|
| 环境 | 可改造：软垫台面、洗衣机垫高、门磁吸、固定俯视相机、筐体秤、停靠导向件（plans-review §0 第 4 条，"能用夹具和场地消掉的难度，不留给模型"） | 不可改造、每户不同 |
| 任务 | 分类 → 洗 → 烘；晾 → 叠 → 收纳（两次交付，[laundry-two-plans-brief.md](laundry-two-plans-brief.md)） | 洗衣全流程 + 收纳、整理、厨房、清洁等长尾 |
| 数据角色 | **数据飞轮起点**：部署即采集，干预段是最贵的对齐层 | 通用能力的检验场；数据隐私约束最强 |
| 对标 | 只有 Dyna 有可指名的商用洗衣客户，且只做"叠"段；"分类 → 洗 → 烘"无公开商用案例（[research-commercial-deployments.md](research-commercial-deployments.md) §3） | Sunday Beta 家庭、Figure 家庭演示，均无规模商用 |

**策略**：先用洗衣房赚到部署数据和可验收的产品，但从第一天起按"家务通用"的标准存数据（§8），让洗衣房数据在进入家庭时仍然可用。

### 4.2 客户的结构性优势（⚠️ 待内部确认）

1. **自有洗衣机 / 烘干机产品线**：可以为机器人开放机器接口（程序启动、门锁、进度、故障码），并有可能读到筒内负载重量、门状态等传感器。这直接消掉卡点 3（R-23："洗烘机器无法由程序启动"），也提供了别家拿不到的事件流与奖励信号。
2. **家庭渠道与售后网络**：可招募真实家庭作为第一视角视频采集点（需单独的同意与脱敏流程，[compliance-and-security.md](compliance-and-security.md)），比外购众包视频更贴近目标家庭分布。
3. **自研本体**：负责人已确认"只服务自研本体，跨品牌不是目标"（U-40 前提）。这让同构采集器路线成本最低，但也意味着**长期通用必须靠数据存法保住**（§8），否则每次本体换代都要从头采。

### 4.3 洗衣场景对数据的特殊要求

| 要求 | 原因 | 落到哪 |
|---|---|---|
| 湿衣分布必须自采 | 外部数据集几乎没有湿布 | 同构采集器 + 遥操作的场地配额（capture-devices-design §1.1） |
| 手被布遮挡 | 视频伪动作通过率低 | 动作真值以同构采集器为主；视频先 50 h 试购测通过率（R-25 触发线 <30%） |
| 筒内深处操作 | 腕相机近距、光线暗 | D405 近距深度（本体规格）；采集器同款同位 |
| 件数与订单一致性 | 漏一只袜子即订单混淆（零容忍项） | 筐体秤 + 腕部扫筒 + 家电负载读数（§5.1 HX-5） |
| 衣物属性 / 洗标 | 分类大脑需要 | 静态图像与洗标标注集（[laundry-sorting-brain-plan.md](laundry-sorting-brain-plan.md)） |

|---|---|---|---|---|---|

### 5.2 HX-2 同构穿戴采集器：关键设计点

在 [capture-devices-design.md](capture-devices-design.md) §1.1–§1.2 的基础上，本文强调四点与训练直接相关的设计：

1. **同件同位**：指部直接用本体末端的零件（同模具、同指面）；腕 / 掌相机同款同安装位姿。这是"零转换直接进动作专家"的前提，验收用"采集 → 本体开环回放"复现成功率 ≥90%（即自变量式物理回放门）。
2. **多视图存储，为换代留后路（F6）**：T/I/S 两节手的数据同时导出"拇食间距 → 二指开合度"的兼容视图（我方判断：T 与 I 的捏取几何可近似投影为二指开合，误差需在样机上实测）。这样两节手时代采的数据可以回喂二指本体的模型，二指时代的数据也可以作为两节手的末端级预训练语料。原始编码器读数永久保留。
3. **力与触觉**：夹持力 200 Hz 必备；两节手指面预留触觉阵列安装位，做 ≤500 h 对照集。
4. **洗衣专项**：VIO 鱼眼朝外上方看环境而非工件；防水护套（湿衣场景）；每段输出 VIO 质量分，低分段只进视频目标；实时提示"超出本体工作空间 / 速度上限"，IK 不可行段标记不删。

**不做**：外骨骼（佩戴负担大、F4 中等，TwinDEX 5.3× 效率依赖其基座，D-03/D-04）；五指灵巧手采集器（本体不是五指，且主被动自由度组合需先做消融，[device-landscape.md](device-landscape.md) §7.2）；Sunday 式手套 + 转换模块（§2.2）。

### 5.3 HX-3 第一视角：自采什么、外购什么

| 来源 | 内容 | 用途 | 约束 |
|---|---|---|---|
| 与 HX-2 同戴的头戴相机 | 洗衣房 / 家庭洗衣区的配对视频 | 标定"视频伪动作 vs 硬件真值"换算率（U-40 的四组对照） | 时钟以 HX-2 为主 |
| 客户员工 / 合作家庭（⚠️ 待内部确认） | 家务全域第一视角视频，洗衣占 ≤40%（我方判断，待消融） | 广度预训练、大脑层场景语义 | 单独同意书、人脸与背景脱敏、隐私硬件三件套（capture-devices-design §6） |
| 外购 | Egocentric-10K（1 万小时，Apache-2.0，工厂场景，无手部标注）；EgoDex（829 h，带手姿）；供应商洗衣视频（先 50 h 试购测通过率） | 预训练打底 | NC 许可集只进研究分支；GR00T 的 EgoScale 未开放（[research-open-ecosystem-2026.md](research-open-ecosystem-2026.md) §0） |

### 5.4 仿真的位置

布料仿真与真机差距大，仿真**不作为训练数据主来源**。预算按 [data-strategy-roadmap.md](data-strategy-roadmap.md) L5 口径：60% 评测孪生与校准（开关门、装卸筐这类刚体部分可做）、30% 长尾、10% 增殖，增殖上限 4:1。X2Real 的 sim-real 相关 0.84 只适用于刚体任务（自报 ⚠️）。

## 6. 数据管线：从采集到训练态

沿用仓库五层结构（recorder → ingest → curation → export → viz），只写客户场景需要新增或强调的部分。

```
HX-1/2/3/4/5 ──► recorder：MCAP（ROS 2 rosbag2 MCAP 后端；采样时刻时间戳；topic 分组 chunk）
                   │  /meta/calibration、/meta/health、end_effector_profile、controller_version
                   ▼
               ingest：校验 → 跨设备对时（视觉↔动作 ≤5 ms，多相机 ≤1 ms）→ AV1 转码 → 幂等入湖
                   ▼
               curation（清洗是标记不是删除）
                 ① 自动质量门：模糊 / 过曝 / 帧间隔 / 同步覆盖率（v0 阈值，需消融）
                 ② 运动学门：本体 IK 可行性、速度包络、工作空间
                 ③ 物理回放门（新）：按任务 × 末端档案抽样，在评测机上开环回放
                 ④ 来源审计、embedding 去重、多样性再平衡（场地 / 衣物 / 高度 / 采集员）
                 ⑤ 分层标注：速度极小值切原子动作 → VLM 写子任务指令（手腕轨迹叠加到帧）
                 ⑥ 家电事件对齐（新）：门开关、负载重量、程序状态 → 子任务边界与成败标签
                 ⑦ 跨模态一致性：指令↔动作、视频↔状态
                   ▼
               export：LeRobot v3（parquet + mp4）；主动作 = 相机系相对末端 + 开合度；
                        action_mask、camera_fov、二指兼容视图；元数据列（质量、速度带、来源、成败）
                   ▼
               训练（§7） ◄── 评测（留出衣物 / 留出站点 / 留出机器）── 回流（HX-4）
```

新增 / 强调的五处：

1. **家电事件流入契约**：`/event/appliance/{door,program,fault}`、`/signal/appliance_load_kg`、`/signal/bin_weight_*`。属于格式改动，按 CLAUDE.md 规则先改 [data-format-contract.md](data-format-contract.md) 再改 schema（本文不改，登记 U-45）。
2. **物理回放门**：自变量的做法（[research-xsquare.md](research-xsquare.md) §9 第 1 条），对 HX-2 尤其必要，它同时是采集器的验收和数据有效性的判据。六台本体中留一台评测机执行（[dyna-replica-plan.md](dyna-replica-plan.md) §12.4）。
3. **洗衣专项 QC**：湿衣段单独标记（湿衣分布是独立的评测切片）；"抓了几件"三信号合判写入段级标签；VIO 低分段降级为只进视频目标。
4. **配对数据的 lineage**：HX-2 与 HX-3 同戴的数据在 lineage 中互相引用，供换算率实验切分。
5. **家庭数据的合规**：家庭视频走单独的同意版本、区域与保留期，人脸与敏感背景脱敏；脱敏对手部可见率的损伤要单独测（U-32）。raw 永存的唯一例外是隐私脱敏与合法删除请求。

## 7. 训练方案

### 7.1 模型结构：三层

| 层 | 频率 | 模型 | 吃什么数据 | 客户专项 |
|---|---|---|---|---|
| **大脑**（S2 等价） | ~1 Hz | 开放权重 VLM 8B 级（Qwen-VL 系）：先提示词 + SOP 状态机，试点前用几千条洗衣标注 SFT | 衣物图像与洗标、头部视角视频、家电状态、子任务指令 | 衣物识别与分筐（[laundry-sorting-brain-plan.md](laundry-sorting-brain-plan.md)）、SOP 编排、成败判别、调用家电接口与站位原语 |
| **小脑**（S1 等价） | ≥10 Hz | 0–5 月：π0.5 后训练（Apache-2.0）；GR00T N1.7 只作研究分支对照（权重 NOML，U-29）；5 月后：自有 S / M 档基座 | 同构真值 + 遥操作 + 回流干预；预训练阶段加视频 | 输出双臂末端增量位姿 + 开合度，经 IK 转关节指令 |
| **本体层**（S0 等价） | ~1 kHz | 自研本体控制器 + 解析原语（站位切换、升降、开关门可选） | — | 不训练；控制器版本冻结到交付边界（U-41 已裁决） |

选择分层的理由见 §2.3；动作头与骨干的选择全部按"≥2 家独立验证"的保守原则（[training-pipeline.md](training-pipeline.md) §1.2）。

### 7.2 四阶段课程

```
Stage A  后训练（0–5 月）
         基座：π0.5；数据：遥操作 + HX-2 同构真值混训
         配比对照：真机固定 + 同构真值 0 / 1× / 10×（自变量模板，自报 ⚠️ D-31）
         通过：交付一过程门（分类准确率 ≥95%、单件抓取 ≥90%，laundry-two-plans-brief §3）

Stage B  自有预训练（按数据门触发，不按日历）
         S 档 0.5B：同构真值 + 视频 ≥1e3 h 时启动，先验证管线与配比
         M 档 2–4B（Qwen-VL 3B/4B 级骨干 + 流匹配 DiT）：≥5e3–1e4 h
         配比起点：human ≥50% / device 20–30% / robot 10–15% / sim ≤15%（L6 口径），
                   洗衣场景按 R-25 实测结果把 device 上调，最终由缩放消融裁决
         目标开关：next_action vs next_action + next_frame（U-37），两条同时训一轮对照
         课程：先离散动作 token 做梯度桥，后切流匹配头
         止损：不优于 Stage A 微调对照 → 回查数据，不加模型

Stage C  任务后训练
         高质量子采样（Sunday 证据，D-25）+ 元数据条件化（推理时提示"高质量、正常速度、成功"）
         物理提示接口预留：上下文里留 3–12 s 演示槽位（GEN-1.5 / Skild S1 方向）

Stage D  闭环强化
         奖励：家电事件流 + 筐体称重对账 + 夹持力成败 + 进度模型
         方法：干预段 DAgger → 冻结基座 + 残差 RL（HIL-SERL 类）
         回流规则：只回流干预段与失败段；升级阶梯 T0 提示库 / 规则 → T1 干预段 SFT
```

### 7.3 视频数据的两种用法，按 R-25 的实测结果二选一或并用

- **R-25 试购通过率 ≥30%**：视频伪动作带可靠性权重进动作目标（ACE-Ego-0 式），同时进 WAM 未来帧目标。
- **通过率 <30%**：视频只进视觉表征与未来帧目标，动作目标完全由 HX-2 与遥操作承担。这正是 Dyna 选择 WAM 的原因：动作不可靠时让视频本身成为监督。
- 两种情况下，生成 / 增殖视频都只进视觉目标，lineage 标 `synthetic=true`。

### 7.4 部署推理

π0 在 Jetson Thor 上 19 Hz（VLA-Perf）。3B 级 VLA + 8B VLM 同机运行需量化并实测（[dyna-replica-plan.md](dyna-replica-plan.md) §12.1）。若 Stage B 选择视频骨干的 WAM，机上跑不到 10 Hz，部署形态按"站点服务器推理"设计（plans-review P-3）；洗衣房有固定网络，这个约束比家庭场景容易满足。

## 8. 长期通用能力的护栏

把"今天为洗衣房采的数据，明年在家庭里还有用"变成可检查的规则：

| 护栏 | 规则 | 检查方式 |
|---|---|---|
| 具身无关的主存储 | 主动作 = 相机系相对末端 + 开合度 / 手关节；关节空间只作次级视图；原始传感器永存 | export 同时产出主视图、二指兼容视图、关节视图；换代时用旧数据在新末端上跑物理回放抽检 |
| 覆盖面优先 | 预训练语料的任务 / 物体 / 环境覆盖作为 KPI（每 1,000 小时计数，Figure 口径 D-09）；P-γ 起非洗衣任务 ≥50% | 每月出覆盖报告；任务向量分析找缺口（U-38） |
| 泛化差距作为验收指标 | 每次评测同时报域内与域外（留出衣物、留出站点、留出机器）成功率之差（Sunday 口径 D-25） | 写入 [eval-protocol.md](eval-protocol.md) 的指标字典 |
| 不删只标 | 失败、恢复、低质量段全部保留，用元数据条件化训练 | 配方 yaml 的 `conditioning` 段（U-30） |
| 骨干可替换 | VLM 骨干取自开放生态，不自研；配方哈希入 lineage | 每次换骨干只重跑 Stage B/C，数据不动 |
| 控制器 / 末端版本隔离 | `controller_version`、`end_effector_profile` 每条必填；跨版本先做混训消融再合并 | ingest 校验必填字段 |
